## 1. Scope Overview

AUTH is the core of the 0.11.0 authentication and RBAC module `com.snoworca.naruserve.utils.auth` inside `NaruServe-api` (research `docs/research/auth-rbac/00.overview.md`, edition 33). It covers the `Auth` builder and its configuration (`AuthConfig`, `AuthMode`, `AuthProfile`, `Deployment`), `auth.install(app)` and the global authentication pipeline (public paths, `protectOnly`, WebSocket upgrade protection, optional authentication), the JSON error model (`AuthRejection`, error code catalog, `auth.errors()`, `auth.errorMiddleware()`), the event model (`AuthEvents`, `AuthEventContext`, `UserOrigin`, `UserChange`), the principal API and guards, `statelessAccess`, the principal cache, bootstrap accounts and first-admin setup/recovery, doctor and `describe()`, audit, `AuthTesting`, and the cross-cutting constraints every other auth scope (TOKEN, FLOW, IAM, APIKEY) relies on: placement and no new dependency, Core-public-API-only, API 21 and Java 8 limits, Kotlin nullability, `TimeSource`, interface evolution and `docs/api` coverage.

## 2. Scope Boundaries

### In Scope

- Placement of the auth module in `NaruServe-api` package `com.snoworca.naruserve.utils.auth` (and subpackages) with no new Gradle module and no new main dependency.
- The rule that `utils.auth` uses only Core public API and never `com.snoworca.naruserve.internal`.
- API 21 (animal-sniffer `android-api-level-21`) and Java 8 conformance of every auth class; no `java.time`, `java.util.Base64`, `java.nio.file`, `CompletableFuture`, `java.util.function`.
- The `TimeSource` SAM in `com.snoworca.naruserve.utils` and epoch-millisecond timestamps in the public auth API.
- Kotlin nullability (`@NullMarked` packages, no platform types), Kotlin-safe names and a Kotlin compile/run test for the new public API.
- `docs/api` reference pages (ko and en) for the auth public API with Express mapping and Java/Kotlin examples.
- `Auth.builder`, secret validation, aggregated `build()` validation, `AuthConfig.load`, `AuthMode`, `AuthProfile`, `Deployment`.
- `auth.install(app)` ordering, wiring, pre-install middleware and CORS rules, public paths, optional authentication, `protectOnly`, WebSocket upgrade protection.
- JSON error handling, `AuthRejection`, the auth error code catalog, `auth.errors()`, `auth.errorMiddleware()` and the request-time error-layer placement check.
- `AuthEvents`, the user-change path/event matrix, `AuthEventContext.getOrigin()`, hash-free event payloads.
- `AuthPrincipal`, `auth.user`/`userOrNull`/`loadUser`, guards `require`/`requireRole`/`authenticated`, `statelessAccess`, the principal cache.
- Bootstrap `.user(...)` seeding, first-admin `POST /auth/setup` and recovery mode.
- doctor, `describe()`, startup log, proxy-trust WARNs, sensitive-value hygiene, audit stream, `AuthTesting`, SPI evolution rule.

### Out of Scope

- v2 items from 00 §9: RS256/ES256 and JWKS, OIDC token acceptance, `ClaimMapping` presets, opaque token introspection (RFC 7662), TOTP and recovery codes, `TenantResolver`/tenancy, mTLS/trusted-header authenticators, `CacheInvalidation` SPI, WebSocket one-time tickets, LDAP `Authenticator` example, `AndroidKeystoreKeySource`, self password reset and email verification, `PUT /auth/admin/groups/:id/roles`, personal-data export/erase endpoints.
- v3 items from 00 §9: `utils.auth.scim` (SCIM 2.0), OIDC RP (code + PKCE), WebAuthn.
- Recommended Core items C5 (server settings read accessor), C1′ (stack hiding in production default errors) and TinyHttpd adapter TLS (00 §8); doctor uses its documented fallback when C5 is absent.
- `NaruServe-kotlin` `req.principal` and reified `attr<T>()` extensions (not in the 0.11.0 v1 row).
- SAML (left to a proxy), embedded policy languages (Casbin, OPA), any built-in database or shared store implementation (JDBC, Redis or other); the application implements the store SPIs (00 §9 out-of-range row; 34판, CON-IAM-003).
- Token, key, password hashing, `MiniJson` and refresh-store details (TOKEN scope); transport modes, CSRF, Origin, endpoint contracts, login throttle, device trust and lockout (FLOW scope); users, groups, roles, grant rule R31 and admin endpoints (IAM scope); API keys and service accounts (APIKEY scope); Core changes C4, C6a, C6b, C7 (APP, HTTP, ENGINE scopes).

## 3. Assumptions and Constraints

- `docs/research/auth-rbac/00.overview.md` (edition 33) is the source of truth; files 01–07 are background and lose every conflict with 00. Values taken only from 01–07 are tagged `[INFERRED:med:advisory]`.
- Type and method names in 00 are proposals; names 00 marks as not final are tagged "(name not final)" and are settled during implementation (CLAUDE.md API 문서 rule).
- The Core changes C4 (registration list and listener), C6a (`req.socketAddress()`), C6b (proxy trust hops/CIDR) and C7 (`req.requestId()`) land in 0.11.0 before the auth pipeline that depends on them.
- `NaruServe-api` keeps zero main dependencies (`':NaruServe-api': [:]`, CON-BUILD-006); no JDBC driver is used in any configuration, test-only included (34판, CON-IAM-003).
- Availability of `java.sql`, `javax.sql.DataSource`, `java.text.Normalizer` and `FileDescriptor.sync()` on API 21 was not yet confirmed by animal-sniffer (00 §12); the build check settles it.
- Android device measurements and the WebView `Origin` behaviour are verification limits (00 §12).

#### Acceptance Criteria

- [ ] AC-1: With setup open, a local request (R33: loopback socket address, no X-Forwarded-* or Forwarded header) with the logged token, username and password creates the user and returns a success response; the same request from a non-local address is rejected and creates nothing, even with the correct token (in PROD a plaintext non-local request is 403 insecure_transport, SEC-FLOW-001 AC-6; a non-local request that passes the R33 transport check is the 403 setup_not_local of AC-8).

- [ ] AC-3: When an admin (holder of *) exists and recovery is off, POST /auth/setup returns 404 NOT_FOUND.

#### Rationale

#### Acceptance Criteria

- [ ] AC-1: In PROD, auth appends at start a final error layer after every layer registered before start (after the app's own error layers, so they answer first): an exception no earlier layer answered gets JSON in the Core shape, a Core HttpException with its status and, below 500, its message, anything else 500 INTERNAL_ERROR with no message, stack trace or exception class; DEV appends no such layer, and auth.errors() and auth.errorMiddleware() still pass other exceptions on (IR-AUTH-002 AC-3).

- [ ] AC-4: app.use("/", auth) installs auth exactly as app.use(auth) does; app.use("", auth) still adds auth as plain middleware.

- [ ] AC-6: The GET /auth/me row and the A3 row of both auth guides say that roles lists the user's own roles only and that auth.user(req).getRoles() holds the roles its groups confer.
