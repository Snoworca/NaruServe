## 1. Scope Overview

This scope covers static files and file responses of NaruServe (issue #12, wave 6): `app.staticFiles(prefix, dir)` mounts and their options (index, directory listing, SPA fallback with its exclusions, cache patterns, MIME overrides), the engine-free `ResourceResolver` with its `java.io.File` implementation, path traversal, hidden-file, canonical-root and symbolic-link checks with the post-open re-check, the MIME registry `app.mimeTypes()`, `CachePolicy`, `res.cache` and the server-wide default `Cache-Control`, `ETag`, `Last-Modified`, conditional `304`, `HEAD`, single byte ranges with `206` and `416`, `If-Range`, `res.file` and `res.download`, the dispatcher's static fallback after explicit routes, and the TinyHttpd `sendFile` hook as a buffered copy. It holds T27, T28, T29, T30, T31, T32 and the static part of T35.

## 2. Scope Boundaries

### In Scope

- Static and file-response types and methods of wave 6 in `NaruServe-api` under `com.snoworca.naruserve` and their internal implementation in `com.snoworca.naruserve.internal`.
- The TinyHttpd adapter's `sendFile` hook in `NaruServe-tinyhttpd`.
- The (미확정) markers owned by #12 in `docs/api/static.md`, `docs/api/response.md` and `docs/api/defaults.md`.

### Out of Scope

- The SAF (Storage Access Framework) resolver (post-v1 P5 item under D-380).
- Zero-copy file transfer for static, `res.file` and `res.download` responses (D-291 allows it; wave 6 does not use it).
- Multi-range (`multipart/byteranges`) responses (D-289 answers several ranges with the full `200`).
- Multipart uploads (scope MULTIPART), WebSocket routes themselves (wave 7) and the Android sample app (wave 8).

## 3. Assumptions and Constraints

- Core code is engine-free code in `NaruServe-api`: it references no TinyHttpd, Servlet, Gson, SLF4J, `android.*` or Kotlin stdlib type, uses `java.io.File` and streams and never `java.nio.file`, compiles to Java 8 bytecode and passes the wave 1 animal-sniffer API 21 checks.
- Public types follow the wave 1 conventions: nullability annotations on public signatures, `@FunctionalInterface` callbacks, Express-style short method names, getter/setter names on value objects, no Kotlin keywords as method names, and no removed or changed public signature of `RestApp`, `Request`, `Response` or the `HttpAdapter` SPI that an earlier wave added: those types gain new methods only (I-014, D-106).
- Where the design leaves a choice open, the wave decisions and the residual section of `docs/research/naruserve-v1/waves/wave-6/design.md` apply; otherwise the implementer decides under standing rule C-07, following RFC 9110 and, between equally valid options, Express behaviour.
- Source of the requirements: `docs/research/naruserve-v1/waves/wave-6/design.md`, `docs/research/naruserve-v1/waves/wave-6/excerpt.md` and `object.md`.
- TinyHttpd at `/Users/beom/work/git/TinyHttpd` stays read-only; gaps become deferred issues under D-020.

#### Requirement

The system shall provide `RestApp staticFiles(String prefix, File dir)` and `RestApp staticFiles(String prefix, File dir, Configurer<StaticOptions> options)` with the options `index`, `directoryListing`, `spaFallback`, `spaExclude`, `cache`, `mime` and `allowSymlinks`, and an engine-free `ResourceResolver` interface in `NaruServe-api` with `open`, `length`, `etag` and `modified` whose built-in `java.io.File` resolver is the only v1 implementation.

#### Rationale

Covers D-256 and D-258 (API part), D-261, D-272 (the symbolic-link allow setting), D-267 (the SPA exclusion setting) and D-409. Builds on IR-HTTP-005 (RestApp surface), IR-APP-007 (`Configurer`) and FR-APP-002 (NEW-state guard). The SAF resolver is a post-v1 (P5) item under D-380, so no public method accepts another resolver in v1. Rejected alternative: a public `staticFiles(prefix, ResourceResolver)` overload; reopen with P5. Re-point convention: `AppLifecycleGuardTest` is re-pointed from AC-5 here.

#### Acceptance Criteria

- [ ] AC-1: `RestApp` declares `staticFiles(String prefix, File dir)` and `staticFiles(String prefix, File dir, Configurer<StaticOptions> options)`, both returning the same `RestApp`; a prefix not starting with `/` throws `IllegalArgumentException`, a `null` argument throws `NullPointerException`, and several calls with different prefixes register several mounts. Decision: a trailing `/` on the prefix is ignored, so `/assets` and `/assets/` name the same mount. [D-256; D-258]
- [ ] AC-2: The public interface `com.snoworca.naruserve.StaticOptions` declares `index(String name)` (default `index.html`), `directoryListing(boolean)` (default `false`), `spaFallback(boolean)` (default `false`), `spaExclude(String... prefixes)`, `cache(String pattern, CachePolicy policy)`, `mime(String ext, String type)` and `allowSymlinks(boolean)` (default `false`), each returning `StaticOptions`. Decision: `allowSymlinks(true)` serves symbolic links below the root while the canonical-root containment still applies, `spaExclude` adds prefixes to the always-excluded `/api/` and `/ws/`, and `mime(ext, type)` accepts `ext` with or without the leading dot (a leading dot is stripped), like `MimeTypes.register`. [D-261; D-272; D-267; D-275]
- [ ] AC-3: The public interface `com.snoworca.naruserve.ResourceResolver` in `NaruServe-api` declares `open`, `length`, `etag` and `modified` and names only `java.io` and `java.lang` types; the built-in `java.io.File` resolver is an internal class and the only implementation in v1, and reflection finds no public or protected method of `RestApp`, `StaticOptions` or `Response` that accepts a `ResourceResolver`. Decision: `InputStream open(String path)`, `long length(String path)`, `String etag(String path)` and `long modified(String path)` take the mount-relative path; for `res.file` and `res.download`, which have no mount, the built-in resolver is rooted at the canonical absolute parent of the named file (FR-STATIC-006 AC-5) and the path is the file's name; the SAF resolver is a post-v1 P5 item under D-380. [D-409; wave decision: The root of res.file and res.download]
- [ ] AC-4: No public or protected signature of `StaticOptions`, `ResourceResolver`, `CachePolicy` or `MimeTypes` names a `java.nio.file` type (reflection test), and the API 21 animal-sniffer check of CON-BUILD-012 passes on `NaruServe-api`. [D-409; D-270]
- [ ] AC-5: `AppLifecycleGuardTest#sdsAc4_FR_APP_002_AC4_reflectionFindsEveryRestAppAndRouteBuilderRegistrationRefusedInRunning`, re-pointed to this requirement, covers the new `RestApp` setters `multipart`, `formLimit`, both `staticFiles` overloads and `defaultCache`, each throwing `IllegalStateException` under the `NEW`-state guard when called after `listen()`, and `mimeTypes().register(...)` after `listen()` also throws `IllegalStateException`. [D-231; D-238; D-256; D-410; D-277]
- [ ] AC-6: A Kotlin test compiles and runs `app.staticFiles("/", dir) { o -> o.index("main.html").spaFallback(true) }` and `app.staticFiles("/assets", File("public"))` without a DSL, then requests `/` and receives `main.html`, with `StaticOptions` a non-platform type. [D-256; D-261; C-03; T11]

#### Requirement

The system shall provide the immutable value object `CachePolicy`, the per-app `MimeTypes` registry returned by `app.mimeTypes()`, the `Response` methods `cache(CachePolicy)`, `file(File)` and `download(File, String filename)`, and `RestApp defaultCache(@Nullable CachePolicy policy)`, while every `RestApp` and `Response` signature of earlier waves stays unchanged.

#### Rationale

Covers D-277, D-278, D-280, D-292 and D-410 (API parts) and the D-293 decision (res.file sends no `Content-Disposition`, like Express `res.sendFile`). Builds on IR-HTTP-001 and IR-HTTP-005 (Response and RestApp surfaces). Re-point convention: `HttpApiSurfaceTest` is re-pointed from AC-5 here, as IR-JSON-002 AC-8 and FR-COOKIE-002 AC-8 did in wave 5. Value-object naming follows CLAUDE.md (`getX()` for Kotlin property syntax). Rejected alternative: a non-null default `Cache-Control`; Express sends none on routes, and a non-empty default would add a header to every response.

#### Acceptance Criteria

- [ ] AC-1: The public final class `com.snoworca.naruserve.CachePolicy` has no public constructor and no setter, provides the static factories `noStore()`, `noCache()`, `privateFor(long amount, TimeUnit unit)` and `publicFor(long amount, TimeUnit unit)`, and `immutable()` returns a new `CachePolicy` while the receiver keeps its value. Decision: the header value is read through `String getHeaderValue()`, so Kotlin reads `policy.headerValue`. [D-278]
- [ ] AC-2: `RestApp mimeTypes()` returns a `MimeTypes` whose `MimeTypes register(String ext, String type)` returns the same registry for chaining; two apps get two independent registries. Decision: `ext` is accepted with or without the leading dot, and a leading dot is stripped, the same rule as `StaticOptions.mime`. [D-277]
- [ ] AC-3: `Response` declares `cache(CachePolicy policy)` returning the same `Response` and the terminal methods `file(File file)` and `download(File file, String filename)`, which end the response like `send`. Decision: `res.file` sends no `Content-Disposition`, like Express `res.sendFile`. [D-280; D-292; D-293]
- [ ] AC-4: `RestApp` declares `defaultCache(@Nullable CachePolicy policy)` returning the same `RestApp`. Decision: the default is `null`, which adds no `Cache-Control` header. [D-410]
- [ ] AC-5: `HttpApiSurfaceTest`, re-pointed to this requirement, checks the wave 6 `RestApp` set (the wave 5 set plus `multipart`, `formLimit`, both `staticFiles` overloads, `mimeTypes` and `defaultCache`, with `create()` and `builder()` still the only static methods and the only new `@Nullable` position the parameter of `defaultCache`) and the wave 6 `Response` set (the wave 5 set plus `cache`, `file` and `download`), with every earlier signature unchanged, and `LATER_WAVE_NAMES` keeps only `sse`. [D-256; D-277; D-280; D-292; D-410; I-014]
- [ ] AC-6: A Kotlin test compiles and runs `val p = CachePolicy.publicFor(365, TimeUnit.DAYS).immutable()`, asserts `p.headerValue == "public, max-age=31536000, immutable"`, and runs a handler calling `res.cache(CachePolicy.noCache())` and `app.mimeTypes().register("webp", "image/webp")`, with no platform type on these positions. [D-278; D-277; D-280; C-03; T11]

#### Requirement

The system shall map `prefix + relative path` of a static mount to the file under its directory, serve the configured index file for a directory path ending in `/`, let several mounts with different prefixes coexist, consult static mounts only after explicit routes, run global middleware on requests that end in a static file, and redirect a directory request without a trailing slash with `301` to the same path plus `/`.

#### Rationale

Covers D-256, D-257, D-258, D-259, D-407 (T27, T35) and the trailing-slash part of D-267 settled by the wave decision "SPA fallback exclusions" (W2-009; `serve-static` behaviour; CVE-2015-1164 open redirect avoided by building `Location` from the raw path and answering `404` for an empty segment; r2 W2-001). Builds on FR-HTTP-022 (fallback point after the route lookup), FR-APP-003 (global middleware) and FR-APP-015 (one access-log line per request).

#### Acceptance Criteria

- [ ] AC-1: With `app.staticFiles("/", root)`, `GET /` returns the bytes of `root/index.html` and `GET /assets/app.js` returns the bytes of `root/assets/app.js`, both `200`. [D-256; T27]
- [ ] AC-2: `GET /docs/` returns `root/docs/index.html`, and with `index("main.html")` it returns `root/docs/main.html` instead. [D-257; D-261; T27]
- [ ] AC-3: With the mounts `/` on `rootA` and `/static` on `rootB`, `GET /static/x.css` returns `rootB/x.css` and `GET /a.txt` returns `rootA/a.txt`; with `spaFallback(true)` on the `/` mount, `GET /static/x.css` with `Accept: text/html` still returns `rootB/x.css`, and `GET /static/missing.css` with `Accept: text/html` receives the SPA index of the `/` mount. Decision: mounts are consulted in registration order and a miss in one mount falls through to the next, as with several Express `static` middlewares; SPA fallback runs only after every mount missed the file lookup, and then the first registered mount with `spaFallback(true)` whose prefix matches the path serves its index. [D-258; D-265]
- [ ] AC-4: With an explicit `GET /index.html` route and a `/` mount whose root holds `index.html`, `GET /index.html` returns the route's body. [D-259; T27]
- [ ] AC-5: A global middleware registered through `app.use` that sets `X-Mw: 1` runs on `GET /assets/app.js` served from a mount, the response carries `X-Mw: 1`, a global middleware that ends the response itself prevents the file from being sent, and one access-log line is written for the static request. [D-407; T35]
- [ ] AC-6: `GET /docs?x=1` for the directory `root/docs` is answered `301` with `Location: /docs/?x=1`; `GET /my%20docs` is answered `301` with `Location: /my%20docs/` built from the raw encoded path; and `GET //assets` is answered `404`, so no `Location` starts with `//` (a T29 case). [wave decision: SPA fallback exclusions; D-267; T29]

### FR-STATIC-002 — Method handling on static paths: 405 Allow GET, HEAD, fall-through after a route's method mismatch, OPTIONS and 501 order

| Field | Value |
| --- | --- |
| Type | functional |
| Target | wave-6 |
| Status | planned |
| Priority | high |
| Tags | wave-6, feasibility:high, static, dispatch, methods |
| Risk | high |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | https://github.com/Snoworca/NaruServe/issues/12 |
| Related Docs | - |

#### Requirement

The system shall answer a non-`GET`/`HEAD` request with `405` and `Allow: GET, HEAD` only when a `GET` for the same path would be answered from the file system by a static mount, let `GET` and `HEAD` fall through to the static mounts when a route matches the path but not the method, keep the route's own `405` and `Allow` otherwise, answer unknown or disabled methods with the router's `501` before any static mount lookup, run the static path checks before the static method decision, and never serve a path owned by a WebSocket route from a static mount.

#### Rationale

Covers D-260, the wave decisions "Static files after a route's method mismatch" (W2-005, r2 W2-004, r3 W2-003; D-259, D-260, D-395, D-265) and "OPTIONS on a static-only path" (W2-006; D-260, D-395; r3 W2-002), and the residual "What served only by a static mount means" (r5 W2-001; D-260, D-262, D-265, D-271, D-395). Builds on FR-HTTP-022 (fallback point, OPTIONS 204 for routes only), FR-ROUTE-010 (the route's own Allow set, no merge), FR-HTTP-021 and FR-ROUTE-004 (path validation `400` before method handling). FR-HTTP-022 scenarios register routes only and stay true. Rejected alternative: merging the route's `Allow` with `GET, HEAD`; the wave decision rejects merged `Allow` values.

#### Acceptance Criteria

- [ ] AC-1: Under `app.staticFiles("/", root)` with no route for the path, `POST /assets/app.js`, `PUT /assets/app.js` and `DELETE /docs/` (a directory with an index file) are answered `405` with `Allow: GET, HEAD`, and the file is not sent. [D-260]
- [ ] AC-2: `OPTIONS /assets/app.js` on a static-only path is answered `405` with `Allow: GET, HEAD`, the automatic `204` of D-395 applies to explicit routes only, and an unknown method token or a disabled `TRACE`/`CONNECT` on that path is answered with the router's `501` before any static mount lookup. Decision: the order is the FR-HTTP-021 AC-2 pre-check order (`OPTIONS *` `204`, raw path not starting with `/` `400`, `PathValidator` `400`, unknown-token `501`), then the router lookup with the disabled `TRACE`/`CONNECT` `501` of FR-HTTP-022 AC-4, then the static mounts, so a `PathValidator` `400` still comes before either `501`. [wave decision: OPTIONS on a static-only path; D-260; D-395]
- [ ] AC-3: With only `POST /login` registered and `root/login` a file, `GET /login` and `HEAD /login` are served from the mount; with `spaFallback(true)` and no file `GET /login` (with `Accept: text/html`) receives the SPA index; with no mount serving it `GET /login` receives the route's `405` with the route's own `Allow`; and `PUT /login` receives the route's `405` with the route's own `Allow`, with no `Allow` values merged. [wave decision: Static files after a route's method mismatch; D-259; D-260]
- [ ] AC-4: A path that a WebSocket route of the router owns is never served from a static mount or by SPA fallback, even when a file of that name exists. Decision: in wave 6, where `app.ws` does not exist yet, the test registers the WebSocket route through the internal router. [wave decision: Static files after a route's method mismatch; D-265]
- [ ] AC-5: The `405` with `Allow: GET, HEAD` applies only when a `GET` for the same path would be answered from the file system (a file, a directory index, a directory listing or the trailing-slash `301`); SPA fallback content does not count, so under a `/` mount with `spaFallback(true)` `POST /missing`, `POST /api/typo` and `POST /.env` receive `404` (a T27 case). A path that D-052 or D-268 rejects receives `400` for every recognised, enabled method because path validation runs before method handling: `POST /a/..%2Fb` and paths with an encoded `/` or `NUL` get the `PathValidator` `400` of FR-HTTP-021; for a path that no explicit route matches and that lies under a static mount prefix, the static D-268 check runs before the static `405`/`404` method decision, so `GET`, `HEAD`, `POST`, `PUT`, `DELETE` and `OPTIONS` of `/%252e%252e/secret.txt` and `/a%252Fb` under a `/` mount all receive `400` (test cases). Explicit routes still take precedence: with `app.post("/:x", h)` registered, `POST /a%252Fb` reaches `h`. [residual: served only by a static mount; D-260; D-262; D-265; D-268; D-271; T27]

### FR-STATIC-003 — Directory without index, escaped directory listing, nosniff header and bounded-chunk streaming

| Field | Value |
| --- | --- |
| Type | functional |
| Target | wave-6 |
| Status | planned |
| Priority | high |
| Tags | wave-6, feasibility:high, static, security |
| Risk | medium |
| Stability | evolving |
| Verification Method | test |
| GitHub Issue | https://github.com/Snoworca/NaruServe/issues/12 |
| Related Docs | - |

#### Requirement

The system shall answer a directory request without an index file with `404` while directory listing is disabled, answer it with an HTML-escaped and percent-encoded `text/html; charset=UTF-8` listing sorted by name when `directoryListing(true)` is set, send `X-Content-Type-Options: nosniff` on static responses, and stream static files in bounded chunks without loading a whole file into the heap.

#### Rationale

Covers D-262, D-420, D-263 and D-264. Builds on FR-HTTP-014 (bounded-chunk stream and commit path) and FR-HTTP-016 (single commit). Pitfall: an unescaped file name in the listing is a stored XSS; names are HTML-escaped in the text and percent-encoded in the link. The listing resolves its directory under the traversal and canonical-root rules of FR-STATIC-005 and FR-STATIC-006 (D-268 to D-271).

#### Acceptance Criteria

- [ ] AC-1: With the default `directoryListing(false)`, `GET /empty/` for a directory without `index.html` is answered `404` with the standard error body. [D-262]
- [ ] AC-2: With `directoryListing(true)`, `GET /files/` for a directory holding `b.txt`, `a b.txt`, `<x>&.txt`, `.hidden` and a symbolic link is answered `200` with `Content-Type: text/html; charset=UTF-8` whose links list `<x>&.txt`, `a b.txt` and `b.txt` in that order, the text showing `&lt;x&gt;&amp;.txt` and the link `href` using `%3Cx%3E%26.txt` and `a%20b.txt`, with no entry for `.hidden` or the symbolic link; `GET /files/..%2F` is answered `400`, and a listing request for a directory reached through a symbolic link below the root is answered `404`. Decision: entries are sorted by `String.compareTo` on the raw, unescaped entry name before any HTML escaping or percent-encoding, so `<` (U+003C) sorts before `a` (U+0061). [D-420; D-268; D-269; D-270; D-271]

#### Requirement

The system shall send `res.file(file)` with its extension's MIME type and no `Content-Disposition`, send `res.download(file, filename)` with `Content-Disposition: attachment` and the filename stripped of header-injection characters, evaluate Range, ETag and conditional requests in engine-free code of `NaruServe-api`, and write static, `res.file` and `res.download` bodies from the `InputStream` the resolver opened and re-checked through the existing `HttpExchange.commit` path.

#### Rationale

Covers D-291, D-292, D-293 and D-409 (behaviour) and the wave decision "File bodies come from the opened stream" (W2-002; D-447, D-291, D-409, D-264): the checked file is the sent file and the SPI signatures stay as frozen (I-014, D-106). D-291 allows zero-copy but does not require it. Builds on CON-HTTP-001 (engine-free core), IR-HTTP-004 (SPI unchanged), FR-HTTP-014 (stream path) and FR-ENGINE-010 (TinyHttpd `sendFile` hook filled as a buffered copy for direct callers). Rejected alternative: `HttpExchange.sendFile` for framework file bodies; it would re-open the file by path after the post-open re-check (TOCTOU).

#### Acceptance Criteria

- [ ] AC-1: `res.file(new File(dir, "report.pdf"))` answers `200` with `Content-Type: application/pdf`, the file bytes and no `Content-Disposition` header, and honours `Range` and conditional headers like a static file. [D-293; D-283; D-287]
- [ ] AC-2: `res.download(file, "report.pdf")` sends `Content-Disposition: attachment; filename="report.pdf"`; for the filename `a\r\nSet-Cookie: x=1".pdf` the header value contains no CR, LF, double quote, backslash or other control character and no `Set-Cookie` header appears in the response. Decision: a non-ASCII filename is also sent as `filename*=UTF-8''` with percent-encoded bytes next to an ASCII `filename` fallback whose non-ASCII characters are replaced by `_`. [D-292]
- [ ] AC-3: The Range, ETag and conditional evaluation classes live in `com.snoworca.naruserve.internal`, reference no adapter, TinyHttpd or Servlet type (core isolation check of CON-BUILD-013), and the T30 and T31 tests pass over the in-memory test adapter and over TinyHttpd. [D-291]
- [ ] AC-4: Static, `res.file` and `res.download` bodies are written from the `InputStream` the resolver opened and re-checked, skipped to the range start and limited to the range length, through `HttpExchange.commit`; a recording test adapter shows that `HttpExchange.sendFile(...)` is never called for them, and the `HttpExchange` SPI signatures are unchanged. [wave decision: File bodies come from the opened stream; D-291; D-264; D-106]
- [ ] AC-5: Static mounts, `res.file` and `res.download` all read through the built-in `java.io.File` `ResourceResolver`, which a test checks by observing its `open`, `length`, `etag` and `modified` calls for each of the three. [D-409]
