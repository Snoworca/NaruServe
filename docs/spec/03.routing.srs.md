## 1. Scope Overview

This scope covers the engine-free router of NaruServe (issues #2 and #3, wave 2): the `Method` enum and the immutable `MethodSet`, route patterns with literal and `:name` segments, the engine-free request path validator, single percent-decoding of path parameters, pattern priority and conflict detection at route-table freeze, the router policies (path form and `TRACE`/`CONNECT` enablement), the six lookup results that the wave 3 dispatcher maps to automatic responses (`404`, `405`, automatic `HEAD`/`OPTIONS`, `426`, `501`), WebSocket route-kind resolution, and the routing semantics recorded in `docs/api/routing.md`. It holds the router-level parts of T01, T02, T03 and T04; the HTTP-level assertions belong to wave 3.

## 2. Scope Boundaries

### In Scope

- `Method`, `MethodSet` and their accessors, in `NaruServe-api` under package `com.snoworca.naruserve` or a subpackage.
- The router: registration with an opaque handler type and a route kind, pattern validation, freeze-time conflict detection, lookup and its six results.
- The engine-free path validator (D-052) and the single percent-decoding of path segments (D-051).
- Router policies: repeated-slash merging, trailing-slash ignoring, case-insensitive static segments, and per-method `TRACE`/`CONNECT` enablement.
- The decided routing semantics and the `MethodSet` accessors in `docs/api/routing.md`.

### Out of Scope

- `Request`, `Response`, `RouteHandler`, `RestApp` and the dispatcher that turns lookup results into HTTP responses (wave 3).
- The names of the routing-policy configuration APIs on `RestApp` and the `req.method()` value during automatic `HEAD` (wave 3, D-398).
- `listen()` and its call of the route-table freeze before binding (wave 4).
- `app.ws` and the WebSocket upgrade handshake (wave 7).
- `OPTIONS *` (D-442) and adapter handling of authority-form `CONNECT` and absolute-form targets (wave 3).
- Any change inside the TinyHttpd checkout.

## 3. Assumptions and Constraints

- The router is engine-free code in `NaruServe-api`: it references no TinyHttpd, Servlet, Gson, `android.*` or Kotlin stdlib type, compiles to Java 8 bytecode and passes the wave 1 animal-sniffer API 21 and class-reference checks.
- Public types follow the wave 1 conventions: nullability annotations on public signatures, no Kotlin keywords as method names.
- Where the design leaves a choice open (accessor names, internal type names), the implementer decides under standing rule C-07 within the constraints the requirements state; open choices follow RFC 9110 and, between equally valid options, Express behaviour.
- Source of the requirements: `docs/research/naruserve-v1/waves/wave-2/design.md` (frozen design items and wave decisions), `docs/research/naruserve-v1/waves/wave-2/excerpt.md` (loop W residual) and `object.md`.

#### Requirement

The system shall provide the public Java enum `Method` with exactly the constants `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`, `TRACE` and `CONNECT`, in that declaration order, and the static factories `Method.get()`, `Method.any()` and `Method.of(Method...)`, each returning a `MethodSet`, with no instance method named after an HTTP method.

#### Rationale

Covers D-030, D-031, D-032 (object.md §3.2).

#### Acceptance Criteria

- [ ] AC-1: `Method.values()` returns exactly `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`, `TRACE`, `CONNECT` in this order. [D-030]
- [ ] AC-2: `Method.get()` returns a `MethodSet` containing only `GET`, `Method.of(Method.PUT, Method.PATCH)` returns a `MethodSet` containing exactly `PUT` and `PATCH`, and `Method.any()` returns a `MethodSet`; all three are static methods of `Method`. [D-031]

#### Requirement

The system shall provide the public immutable class `MethodSet` whose combinators `get()`, `head()`, `post()`, `put()`, `patch()`, `delete()` and `options()` each return a new set with that method added, and whose `except(Method)` returns a new set without the given method, every combinator leaving the receiver unchanged.

#### Rationale

Covers D-033, D-034, D-035 (T01, T02 set parts).

#### Acceptance Criteria

- [ ] AC-1: For `MethodSet s = Method.get()`, calling `s.post()` returns a set containing `GET` and `POST`, and `s` still contains only `GET` afterwards; the same holds for every combinator and for `except`. [D-033]
- [ ] AC-2: `Method.get().delete().post()` contains exactly `GET`, `DELETE` and `POST`, and each of `get()`, `head()`, `post()`, `put()`, `patch()`, `delete()` and `options()` adds exactly its own constant to the receiver's members. [D-034]
- [ ] AC-3: `Method.get().post().except(Method.POST)` contains exactly `GET`, and `except` of a method that is not a member returns a set equal to the receiver. [D-035]
- [ ] AC-4: `MethodSet` has no public constructor or mutator, its fields are final, and any iterator or collection it exposes is unmodifiable (`remove` throws `UnsupportedOperationException`). [D-033]

#### Requirement

The system shall accept route patterns made of literal segments and `:name` variable segments, where a variable matches exactly one non-empty path segment and never crosses `/`, and shall fail registration with a configuration error for a pattern that contains Express wildcard or regular-expression syntax, an empty variable name, a variable name repeated within the pattern, or an empty segment.

#### Rationale

Covers D-047, D-048, the wave decision on pattern validation (empty or repeated variable name is a configuration error at registration time) and the loop W residual (a pattern containing an empty segment such as `/a//b` is a configuration error). Reporting the empty-segment error at registration, together with the other pattern errors, is the implementer's choice under C-07.

#### Acceptance Criteria

- [ ] AC-1: `/users/:id` matches `/users/42` with `id` = `42`, and matches neither `/users`, `/users/` nor `/users/42/posts`. [D-047]
- [ ] AC-2: Registering a pattern containing `?`, `*`, `+`, `(` or `)` fails with a configuration error. [D-048]
- [ ] AC-3: Registering `/a/:` or `/a/:id/:id` fails with a configuration error at registration time. [wave decision: pattern validation]
- [ ] AC-4: Registering `/a//b` fails with a configuration error, while `/` and a pattern with one trailing slash such as `/users/` are accepted. [loop W residual: empty segment]

### FR-ROUTE-004 — Engine-free request path validator

| Field | Value |
| --- | --- |
| Type | functional |

| Status | planned |
| Priority | critical |
| Tags | wave-2, feasibility:high, routing, security, path-validation |

#### Requirement

The system shall provide an engine-free path validator, run before the router lookup by the wave 3 dispatcher and every adapter, that inspects the raw request path without decoding it and rejects malformed percent-encoding, percent-encoded bytes that are not valid UTF-8, raw non-ASCII characters, an encoded `/`, an encoded or raw `NUL`, and any `.` or `..` segment in raw or percent-encoded form, matching the rules TinyHttpd's parser applies.

#### Rationale

Covers D-052 and the wave decision on path validation before lookup (W2-003, W2-004), plus the loop W residual (the validator inspects the raw path and does not decode it). Mapping a rejection to `400` is the wave 3 dispatcher's job; the router lookup returns only the six results of D-390.

#### Acceptance Criteria

- [ ] AC-1: The validator rejects `/a%2`, `/a%zz`, `/a%C3` (truncated UTF-8), `/a%FF`, a path containing a raw character above U+007F, `/a%2Fb`, `/a%2fb`, `/a%00`, a path containing a raw U+0000, `/./a`, `/a/..`, `/a/%2e`, `/a/%2E%2e` and `/a/.%2e/b`. [D-052]
- [ ] AC-2: The validator also rejects, as TinyHttpd's request-target parser does, a path containing a raw space, a raw control character U+0001..U+001F, U+007F or `#`. [D-052]
- [ ] AC-3: The validator accepts `/users/42`, `/files/%252e`, `/caf%C3%A9` and `/a/.hidden`, and its result is the same whether or not a query string follows the path. [D-052; D-051]
- [ ] AC-4: The validator returns an accept or reject decision without returning a decoded path, and the router lookup API has no result variant for a rejected path. [loop W residual; wave decision: path validation before lookup]
