## 1. Scope Overview

This scope covers the engine-free router of NaruServe (issues #2 and #3, wave 2): the `Method` enum and the immutable `MethodSet`, route patterns with literal and `:name` segments, the engine-free request path validator, single percent-decoding of path parameters, pattern priority and conflict detection at route-table freeze, the router policies (path form and `TRACE`/`CONNECT` enablement), the six lookup results that the wave 3 dispatcher maps to automatic responses (`404`, `405`, automatic `HEAD`/`OPTIONS`, `426`, `501`), WebSocket route-kind resolution, and the routing semantics recorded in `docs/api/routing.md`. It holds the router-level parts of T01, T02, T03 and T04; the HTTP-level assertions belong to wave 3.

## 2. Scope Boundaries

### In Scope

- `Method`, `MethodSet` and their accessors, in `NaruServe-api` under package `com.snoworca.naruserve` or a subpackage.
- The router: registration with an opaque handler type and a route kind, pattern validation, freeze-time conflict detection, lookup and its six results.
- The engine-free path validator (D-052) and the single percent-decoding of path segments (D-051).
- Router policies: repeated-slash merging, trailing-slash ignoring, case-insensitive static segments, and per-method `TRACE`/`CONNECT` enablement.
- The decided routing semantics and the `MethodSet` accessors in `docs/api/routing.md`.

### Out of Scope

- `Request`, `Response`, `RouteHandler`, `RestApp` and the dispatcher that turns lookup results into HTTP responses (wave 3).
- The names of the routing-policy configuration APIs on `RestApp` and the `req.method()` value during automatic `HEAD` (wave 3, D-398).
- `listen()` and its call of the route-table freeze before binding (wave 4).
- `app.ws` and the WebSocket upgrade handshake (wave 7).
- `OPTIONS *` (D-442) and adapter handling of authority-form `CONNECT` and absolute-form targets (wave 3).
- Any change inside the TinyHttpd checkout.

## 3. Assumptions and Constraints

- The router is engine-free code in `NaruServe-api`: it references no TinyHttpd, Servlet, Gson, `android.*` or Kotlin stdlib type, compiles to Java 8 bytecode and passes the wave 1 animal-sniffer API 21 and class-reference checks.
- Public types follow the wave 1 conventions: nullability annotations on public signatures, no Kotlin keywords as method names.
- Where the design leaves a choice open (accessor names, internal type names), the implementer decides under standing rule C-07 within the constraints the requirements state; open choices follow RFC 9110 and, between equally valid options, Express behaviour.
- Source of the requirements: `docs/research/naruserve-v1/waves/wave-2/design.md` (frozen design items and wave decisions), `docs/research/naruserve-v1/waves/wave-2/excerpt.md` (loop W residual) and `object.md`.

#### Requirement

The system shall provide the public Java enum `Method` with exactly the constants `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`, `TRACE` and `CONNECT`, in that declaration order, and the static factories `Method.get()`, `Method.any()` and `Method.of(Method...)`, each returning a `MethodSet`, with no instance method named after an HTTP method.

#### Rationale

Covers D-030, D-031, D-032 (object.md §3.2).

#### Acceptance Criteria

- [x] AC-1: `Method.values()` returns exactly `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`, `TRACE`, `CONNECT` in this order. [D-030]
- [x] AC-2: `Method.get()` returns a `MethodSet` containing only `GET`, `Method.of(Method.PUT, Method.PATCH)` returns a `MethodSet` containing exactly `PUT` and `PATCH`, and `Method.any()` returns a `MethodSet`; all three are static methods of `Method`. [D-031] [SDS 2026-10-19.naruserve.naruserve-v1-wave-2-1 SDS-AC-2] `Method.of` throws `NullPointerException` for a null array or a null element.
- [x] AC-3: Reflection over `Method` finds no non-static method, and no static method other than `get()`, whose name is `get`, `head`, `post`, `put`, `patch`, `delete`, `options`, `trace` or `connect` (case-insensitive), so `Method.GET.delete()` does not compile. [D-032]

#### Requirement

The system shall provide the public immutable class `MethodSet` whose combinators `get()`, `head()`, `post()`, `put()`, `patch()`, `delete()` and `options()` each return a new set with that method added, and whose `except(Method)` returns a new set without the given method, every combinator leaving the receiver unchanged.

#### Rationale

Covers D-033, D-034, D-035 (T01, T02 set parts).

#### Acceptance Criteria

- [x] AC-1: For `MethodSet s = Method.get()`, calling `s.post()` returns a set containing `GET` and `POST`, and `s` still contains only `GET` afterwards; the same holds for every combinator and for `except`. [D-033] [SDS 2026-10-19.naruserve.naruserve-v1-wave-2-1 SDS-AC-4] Every combinator, `with` and `except` returns a different `MethodSet` instance unless the members are unchanged, and leaves the receiver's members unchanged.
- [x] AC-2: `Method.get().delete().post()` contains exactly `GET`, `DELETE` and `POST`, and each of `get()`, `head()`, `post()`, `put()`, `patch()`, `delete()` and `options()` adds exactly its own constant to the receiver's members. [D-034]
- [x] AC-3: `Method.get().post().except(Method.POST)` contains exactly `GET`, and `except` of a method that is not a member returns a set equal to the receiver. [D-035]
- [x] AC-4: `MethodSet` has no public constructor or mutator, its fields are final, and any iterator or collection it exposes is unmodifiable (`remove` throws `UnsupportedOperationException`). [D-033]

#### Requirement

The system shall give `MethodSet` a membership accessor and an iteration accessor that yields members in `Method` declaration order, both named by the implementer (C-07) without Kotlin keywords, and value equality, so that two sets with the same members are equal and have equal hash codes.
