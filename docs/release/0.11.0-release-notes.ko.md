# NaruServe 0.11.0

[English](0.11.0-release-notes.md) | 한국어

0.11.0은 `naruserve-api`에 내장 인증·RBAC 모듈 `com.snoworca.naruserve.utils.auth`를 더합니다. 선택 기능이라 `Auth`를 만들지 않는 앱은 0.10.0과 똑같이 동작합니다.

## 인증과 RBAC

- `Auth.builder(secret)...build()`와 `app.use(auth)`로 `/auth` 아래에 JWT 로그인·갱신·로그아웃, 프로필·비밀번호 엔드포인트가 생기고, 그 밖의 경로는 모두 기본 거부됩니다. 공개 경로는 `.permit(...)`과 `.permitPrefix(...)`로 엽니다.
- 역할과 스코프는 `RolePolicy`(또는 `RoleStore`)에서 오고, 가드는 `auth.require(scope)`, `auth.requireRole(role)`, `auth.check(rule)`, `auth.authenticated()`입니다. 부모 그룹을 둘 수 있는 그룹이 `GroupStore`를 통해 역할을 줍니다.
- `/auth/admin` 아래의 관리자 엔드포인트로 사용자·그룹과, `.apiKeys(store)`가 있으면 API 키를 관리합니다. 개인 API 키는 `/auth/me/apikeys`에서 발급합니다.
- 저장은 SPI(`UserStore`, `RefreshTokenStore`, `LoginThrottle`, `DeviceTrust`, `GroupStore`, `ApiKeyStore`) 뒤에 있습니다. 메모리 저장소와 파일 저장소가 함께 오고, 파일 속 비밀은 `AuthFileKey`로 암호화합니다. 앱이 직접 만든 저장소는 `AuthTesting.verifyUserStore`로 점검합니다.
- 기동 doctor는 약한 비밀키, 암호화하지 않은 파일 저장소, auth 뒤에 등록한 CORS 같은 실수가 있으면 PROD 기동을 멈추고, 선언하지 않은 역할·스코프 같은 오타에는 WARN을 남깁니다. `AuthMode.DEV`는 로컬 작업을 위해 PROD 규칙을 늦춥니다.
- 오류 응답은 JSON이고 고칠 방법을 알려 줍니다. 잘못된 경로·메서드, 잘못된 자리의 토큰·키, 모르는 본문 필드, 액세스 토큰 자리에 보낸 refresh 토큰 등이 그렇습니다. PROD에서는 auth가 기동할 때 붙이는 마지막 오류 층이 앱 예외를 스택 트레이스 없는 JSON으로 답합니다.

## Core

- `Installable`: `x`가 이를 구현하면 `app.use(x)`와 `app.use("/", x)`가 `x.install(app)`을 부릅니다. `app.use(auth)`는 `auth.install(app)`과 같습니다. `""`·`"/"`가 아닌 경로로 쓰면 `IllegalArgumentException`을 던집니다.
- `app.registrations()`는 앱에 등록된 것을 순서대로 보여 주고, `app.onRegistration(listener)`는 새 등록을 지켜봅니다.
- `app.trustProxyHops(n)`과 `app.trustProxyCidrs(...)`로 프록시를 홉 수나 주소 범위로 신뢰합니다.

## 0.10.0에서 올리기

버전만 **0.11.0**으로 바꾸면 됩니다. `Installable`을 `app.use("/", x)`로 쓰면 이제 보통 미들웨어로 더하지 않고 install합니다. 함께 나가는 모듈에서 `Installable`을 구현한 것은 `auth`뿐입니다. 런타임 의존성은 그대로입니다.

## 설치와 검증

모든 모듈은 `com.snoworca.naruserve`와 버전 **0.11.0**을 씁니다. [README 설치 안내](../../README.ko.md#설치)와 [auth 안내서](../api/auth.md)를 보세요.

Core는 Java 8을 대상으로 하고, 소스 빌드는 JDK 17과 Gradle 8.14.3을 씁니다. API 21 시그니처 검사는 빌드에서 돌며, 기기 실행이 아닌 정적 증거입니다.
