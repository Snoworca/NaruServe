# NaruServe 0.10.0

[English](0.10.0-release-notes.md) | 한국어

0.10.0은 일반 HTTP 라우팅을 Express 5 공통 프로파일에 맞추면서 Java 정규식과 NaruServe 확장을 유지합니다. 차등 검증 코퍼스는 Express 5.1.0을 고정합니다. JavaScript 정규식이나 WebSocket API까지 같다는 뜻은 아닙니다.

## 라우팅과 요청 API

- 라우트·미들웨어·마운트·오류 처리기는 등록 순서대로 실행됩니다. 반환된 `RouteBuilder`는 나중에 핸들러를 추가해도 자신의 식별성과 생성 시점의 등록 위치를 유지하며 일반 HTTP 등록은 실행 중에도 추가할 수 있습니다.
- 공개 `Router`는 중첩 마운트, 로컬 라우팅 옵션, `mergeParams`, 매개변수 콜백을 지원합니다. 요청 객체는 유지하면서 현재 URL·base URL·매개변수 뷰가 활성 마운트를 따릅니다.
- 문자열 경로는 이름 있는 매개변수·와일드카드 목록·중괄호 선택 그룹을 지원합니다. 경로 대안과 Java `Pattern`도 같은 등록 API를 사용합니다. 원래 Java 정규식 소스와 플래그를 정확히 유지해야 하면 `RegexPathPattern.compile(source, flags)`를 사용하세요.
- 저장한 `Next`는 콜백 반환 후에도 재개할 수 있습니다. `route()`와 `router()`는 해당 범위를 건너뜁니다. HEAD 대체 처리, Router별 OPTIONS, 메서드 토큰 라우팅은 공통 HTTP 계약을 따릅니다.

## 지연 작업과 오류

`getAsync`·`methodAsync`·`useAsync` 콜백은 `Deferred`를 반환합니다. 반환한 pending 결과는 먼저 응답을 보낸 뒤에도 본문·업로드 소유권을 유지합니다. 생산자가 마지막 자원 접근을 마친 뒤 settle하세요. resolve는 다음 라우트 실행이나 응답 종료를 대신하지 않습니다. 취소와 강제 종료 뒤에는 늦은 작업이 요청을 다시 열 수 없습니다.

일반 HTTP의 미처리 경로는 HTML 404, 처리되지 않은 예외는 Java 예외 정보·스택을 이스케이프한 HTML로 응답합니다. 오류를 처리할 라우트 뒤에 오류 미들웨어를 등록하고, JSON 계약이 필요하면 직접 JSON을 보내세요. 요청 생성 전·수명주기·기존 legacy/WebSocket의 JSON 오류 경로는 별도로 유지됩니다.

## 호환성과 이전

| 이전 가정 | 0.10.0 일반 HTTP 계약 |
|---|---|
| 이름 없는 와일드카드·접미 선택 표시 | 이름 있는 와일드카드와 중괄호 그룹 사용: 라우팅 가이드 참고 |
| 문자열 하나인 경로 매개변수 | 이름 있는 와일드카드는 타입을 지정한 목록 접근자로 읽기 |
| 콜백 반환 시 응답 종료 | 응답·continuation·지연 작업 소유권을 명시적으로 처리 |
| 전역 오류 순서·기본 JSON | 순서에 맞춰 오류 콜백을 등록하고 JSON을 명시적으로 선택 |

타입을 지정한 본문 읽기, 입력 제한, CORS 개인정보 보호, 정적 파일 경로 보호, 앱 서비스, SSE, 기존 WebSocket 확장은 유지합니다. WebSocket은 별도의 엄격한 라우팅 프로파일을 유지합니다. TinyHttpd 어댑터는 공개된 core/websocket **3.1.1**과 명시적 RAW request-target 전달을 사용합니다. 다른 외부 버전과 의존성 범위는 바꾸지 않았습니다.

사용자 어댑터의 SPI 기본 메서드는 소스 호환성을 유지합니다. 실제 지연 요청 소유권을 제공하려면 `onAbort`와 `retainRequest`를 구현하세요. 선택적인 `responseStatus`·`responseBytesWritten` 관측값은 어댑터 자체 오류의 접근 로그를 정확히 기록하며, 알 수 없을 때의 기본값은 `0`·`-1`입니다.
