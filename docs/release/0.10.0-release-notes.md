# NaruServe 0.10.0

English | [한국어](0.10.0-release-notes.ko.md)

0.10.0 aligns the common HTTP routing profile with Express 5 while retaining Java regular expressions and NaruServe extensions. The differential corpus pins Express 5.1.0; it does not claim JavaScript regular-expression or WebSocket API equivalence.

## Routing and request APIs

- Routes, middleware, mounts and error handlers execute in registration order. Each returned `RouteBuilder` retains its identity and creation-time registration position when handlers are added later; ordinary HTTP registrations can be appended while running.
- Public `Router` instances support nested mounts, local routing options, `mergeParams` and parameter callbacks. A request retains its identity while its current URL, base URL and parameter view follow the active mount.
- String paths support named parameters, named wildcard lists and brace-delimited optional groups. Alternatives and Java `Pattern` paths use the same registration surface. Use `RegexPathPattern.compile(source, flags)` when the original Java source and flags must be preserved precisely.
- Saved `Next` callbacks can resume after return. `route()` and `router()` skip the corresponding scope. HEAD fallback, router-local OPTIONS and method-token routing follow the common HTTP profile.

## Deferred work and errors

`getAsync`, `methodAsync` and `useAsync` accept callbacks returning `Deferred`. A pending returned result retains request body/upload ownership after an early response; settle after the producer's final resource access. Resolving neither advances routing nor finishes a response. Cancellation and forced shutdown prevent late work from reopening the request.

Unhandled common HTTP fallthrough produces HTML 404; unhandled exceptions produce escaped HTML with Java exception details and stack frames. Register error middleware after the routes whose failures it should handle, and send JSON explicitly when that is your API contract. Pre-request, lifecycle and retained legacy/WebSocket JSON paths remain distinct.

## Compatibility and migration

| Previous assumption | 0.10.0 common HTTP contract |
|---|---|
| Bare wildcard or postfix optional marker | Use named wildcards and brace groups; see the routing guide |
| Scalar-only route parameters | Read named wildcard lists through the typed list accessors |
| Callback return ends the response | Explicitly respond, continue, or retain deferred work |
| Global error ordering/default JSON | Register ordered error callbacks and select JSON explicitly |

Typed body reads, bounded inputs, CORS privacy, static-file containment, application services, SSE and existing WebSocket extensions remain available. WebSocket routing retains its separate strict profile. The TinyHttpd adapter uses the published core/websocket **3.1.1** artifacts with explicit RAW request-target delivery; other external pins and dependency scopes are unchanged.

Custom exchanges retain source-compatible SPI defaults. Implement `onAbort` and `retainRequest` to provide real deferred transport ownership. Optional `responseStatus`/`responseBytesWritten` observations let adapter-generated errors retain correct terminal access-log metrics; their unknown defaults are `0`/`-1`.
