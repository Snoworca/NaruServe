# NaruServe 0.12.0

English | [한국어](0.12.0-release-notes.ko.md)

0.12.0 adds two things: the raw access API in `naruserve-api`, for apps that need the request and response as they travel on the wire, and the new module `naruserve-proxy`, a reverse proxy middleware built on that API. An app that uses neither behaves as in 0.11.0, except that an unwrapped `BodyTooLargeException` now answers `413` (see [Upgrading from 0.11.0](#upgrading-from-0110)).

## Raw access API

- `req.bodyStream()` and `req.bodyStream(maxBytes)` return the request body as received, as an `InputStream` (only the chunked transfer coding is removed; `Content-Encoding` is kept). `app.rawBodyLimit(bytes)` sets the default limit (1 MiB). A declared `Content-Length` over the limit throws `HttpException` `413` at the call; a chunked body throws `BodyTooLargeException` from the stream when it passes the limit. The body is still read once: after `bodyStream`, `body(...)`, `form(...)` and `parts()` throw `BodyAlreadyConsumedException`.
- `req.headerNames()` (lowercase names) and `req.rawHeaders()` (name-value pairs with their case and duplicates) enumerate the request headers.
- `req.socketAddress()` is the real connection peer, independent of proxy settings, and `req.isFromTrustedProxy()` tells whether the app's proxy trust setting (`trustProxyHops`, `trustProxyCidrs`) trusts that peer.
- `res.append(name, value)` adds a header line without replacing one of the same name, like Express `res.append`.
- `res.onAbort(listener)` runs a listener once when the response ends abnormally, for example when the client disconnects.
- `res.relay(in, contentLength)` streams a body and keeps the given length as `Content-Length` (`-1` leaves the framing to the adapter); it adds no `Content-Type` and no default cache header.
- `HttpHeaderValues.isToken(name)` and `HttpHeaderValues.isFieldValue(value)` in `com.snoworca.naruserve.common` expose the header check that `res.header` and `res.append` apply.
- `BodyTooLargeException` is public in `com.snoworca.naruserve` (it was internal), with a public constructor and `limit()`.

The guides: [Request](../api/en/request.md) and [Response](../api/en/response.md).

## NaruServe-proxy

`com.snoworca.naruserve:naruserve-proxy` depends on `naruserve-api` only; `naruserve`, `naruserve-kotlin` and `naruserve-android` do not include it, so only an app that proxies adds it. Its main classes target Java 8 and pass the API 21 signature check.

- `app.use("/api", Proxy.to("http://127.0.0.1:8081"))` forwards the requests under a path to one backend and relays its response, like `http-proxy-middleware`. A `Proxy` is immutable; every option returns a new one and checks its value when it is called.
- Options: connect, write, read and total timeouts, retries (only for idempotent methods by default), `stripPrefix`, `preserveHost`, `bodyLimit`, `maxConcurrent`, fixed request and response headers, and `Location` rewriting. `X-Forwarded-For`, `X-Forwarded-Proto` and `X-Forwarded-Host` are set by fixed rules.
- Failures before the response reach `app.onError` as a `ProxyException` whose `kind()` names the cause (`CONNECT_FAILED`, `WRITE_TIMEOUT`, `READ_TIMEOUT` and so on) and answer `502`, `503` or `504` without the backend address.
- `https` backends are verified (certificate chain and host name, always on). `trustCertificates(String pem)` and `trustCertificates(X509Certificate...)` trust exactly the given certificates, for a self-signed backend or a private CA; `sslSocketFactory(...)` takes a full TLS configuration.

The guide: [Reverse proxy](../api/en/proxy.md).

### Declared limits

- The proxy sends the whole request body to the backend before it reads the response (half-duplex). A backend that answers while it is still reading a large upload (a streaming echo) stalls both sides, and the request ends in `504` (`WRITE_TIMEOUT`) once `writeTimeout` passes.
- On the JVM, a backend chain that holds an MD5-signed certificate gets `502` (`CONNECT_FAILED`) with `trustCertificates`, even when the path does not need that certificate. The JDK wrapper of a trust manager rejects it, and the fix (`X509ExtendedTrustManager`) needs API 24.
- Every backend request opens a new connection (no pool), and a proxied request holds one request thread until it ends.
- No Android device or emulator run took place. API 21 compatibility rests on `--release 8` and the animal-sniffer `android-api-level-21` check, which covers `NaruServe-proxy`; `trustCertificates` under Conscrypt is untested.

## Upgrading from 0.11.0

Change the version to **0.12.0**. Two behaviours change:

- An unwrapped `BodyTooLargeException` that reaches the error flow now answers `413`; 0.11.0 answered `500`. A wrapped one is still handled as an ordinary exception.
- `BodyTooLargeException` moved from `com.snoworca.naruserve.internal` to `com.snoworca.naruserve`; code that imported the internal class must change the import.

`Request` and `Response` gained methods. A class that implements either interface itself still compiles, because the new methods have default implementations that throw `UnsupportedOperationException`. Runtime dependencies are unchanged; `naruserve-proxy` adds none besides `naruserve-api`.

## Installation and verification

All modules use `com.snoworca.naruserve` and version **0.12.0**; `naruserve-proxy` is the eleventh artifact. See the [README installation instructions](../../README.md#install), the [reverse proxy guide](../api/en/proxy.md) and the [request guide](../api/en/request.md).

The core targets Java 8; source builds use JDK 17 and Gradle 8.14.3. API 21 signature checks run in the build; they are static evidence, not a device run.
