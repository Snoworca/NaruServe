### `trustCertificates` (FR-PROXY-022)

The user asked that https backends with non-public certificates be reachable, and chose the option "trust the given certificates" (recommended). PRD-165 is unchanged.

- `Proxy.trustCertificates(String pem)` and `Proxy.trustCertificates(X509Certificate...)` trust exactly the given certificates. The chain and the host name are still checked (`CertificateHostnames`, SAN only).
- Only given certificates that are currently valid act as trust anchors. The platform `X509TrustManager` builds the path and checks signatures, basicConstraints, keyUsage, pathLen and validity. If no given certificate is valid, the connection fails with 502 `CONNECT_FAILED`.
- Every connection runs a full TLS handshake. No session is resumed, so trust is decided again on each connection; the measured median cost is 0.010 ms.
- PEM input is checked when the option is set. A block that does not decode to exactly one DER certificate throws `IllegalArgumentException`.
- Whichever of `sslSocketFactory` and `trustCertificates` is called later wins.
- Docs: `docs/api/proxy.md` and `docs/api/en/proxy.md`, with the Express `ca` counterpart, Java and Kotlin examples and an `openssl` command that makes a usable self-signed certificate.
- Tests: `ProxyTrustCertificatesTest` (35) and `ProxyTrustCertificatesKotlinTest` (2). Certificates are made with `keytool` at test time; no key is committed.

Loop P ran six rounds on this addition (`waves/post-run/loop-p-trustcerts-r1.json` to `r6.json`):

- **Rounds 1 to 5** each kept at least one finding: anchor validity, cross-signed and renewed CAs, a non-CA copy of a CA, off-path expired certificates, and session resumption skipping the trust decision. Each was fixed tests-first by an independent fixer.
- **Round 4:** the design switched from a hand-written path search to the platform trust manager.
- **Round 6** was clean.

FR-PROXY-022, IR-PROXY-001, SEC-PROXY-005 and OPS-DX-010 were verified after round 6 (`e1a2a94`).

**Declared limitation (JVM):** the JDK wraps a trust manager that does not extend `X509ExtendedTrustManager`, and that wrapper rejects a chain holding an MD5-signed certificate even when the path does not need it, which gives 502. `X509ExtendedTrustManager` needs API 24, so the API 21 module cannot use it. The limitation is documented and pinned by `fr_PROXY_022_AC7_declaredLimitation_onTheJvmAnUnneededMd5SignedCertificateIsConnectFailed`.
