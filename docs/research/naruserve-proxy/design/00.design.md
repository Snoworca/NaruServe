# NaruServe raw access API and reverse proxy — run design

This is the run design for `2026-11-14.NaruServe.naruserve-proxy`. It turns the request document (`docs/naruserve-proxy-request.md`, recorded verbatim as `U-1` of `docs/prd/2026-11-14.naruserve-proxy.prd.md`) and the three intake investigations (`intake/intent.json`, `intake/code_context.json`, `intake/existing_srs_context.json`) into numbered design items. The request already fixes most behaviour through its sections, its acceptance criteria and the recommended option of each decision; the items below record placement, the API shape the request leaves open, and the default chosen for every ambiguity the intent investigator found (AMB-1 to AMB-29) and its one contradiction (CON-1). Each item ends with its PRD basis.

## 2. Request A — raw access API

### Body stream

- [D-010] `Request` SHALL gain `bodyStream()` and `bodyStream(long maxBytes)` returning `InputStream`, implemented by `DefaultRequest`. ← PRD-15
- [D-011] The existing package-private `DefaultRequest.bodyStream()` SHALL be renamed, with every internal reader moved to the new name, before the public method is added. ← PRD-269
- [D-012] Calling `bodyStream` with any limit SHALL mark the body as taken for every other reader, so `body(...)`, `form(...)` and `parts()` called afterwards throw `BodyAlreadyConsumedException` whatever the content type. fills: PRD-16 / hole / AMB-1, the request does not say whether a bare call takes the body
- [D-013] A repeated `bodyStream` call SHALL return the first stream object only while no byte has been consumed and the limit is equal, where a `read` or `skip` that advances and a `close` count as consumption and `available` does not. fills: PRD-17 / hole / AMB-2, the request does not define which stream operations consume
- [D-014] When the declared `Content-Length` exceeds the limit in force, `bodyStream` SHALL throw `HttpException` with status 413 before reading any byte. ← PRD-184
- [D-015] When the length is not declared, reading past the limit SHALL throw `BodyTooLargeException` from the stream. ← PRD-23
- [D-016] Bytes read through `bodyStream` SHALL pass the same counting path as the other body readers, so the access log `in=` field reports them. ← PRD-186
- [D-017] A body stream left unread or unclosed by the handler SHALL be drained and released by the framework at the end of the request through the existing cleanup path. ← PRD-19
- [D-018] A request without a body SHALL get an empty, non-null stream from `bodyStream`. ← PRD-183

### Raw body limit

- [D-019] `RestApp` SHALL gain `rawBodyLimit(long bytes)` with the same state guard, range `1..1073741824` and 1 MiB default as `jsonLimit` and `formLimit`, throwing `IllegalArgumentException` outside the range. ← PRD-21
- [D-020] `bodyStream(long maxBytes)` SHALL validate its argument against the same range and throw `IllegalArgumentException` outside it. ← PRD-22

### Over-limit exception

- [D-021] `BodyTooLargeException` SHALL move to the public package `com.snoworca.naruserve` as a public final `IOException` subclass keeping its `(long limit)` constructor and `limit()` accessor, with no alias left in `internal`. ← PRD-24
- [D-022] `StandardErrors.statusOf` SHALL map an unwrapped `BodyTooLargeException` to status 413 while a wrapped one stays an ordinary exception. ← PRD-25
- [D-023] The TinyHttpd adapter SHALL refer to the TinyHttpd exception of the same simple name by its fully qualified name. fills: PRD-24 / defect / AF-11, both classes are named BodyTooLargeException

### Header enumeration and append

- [D-024] `headerNames()` SHALL return an unmodifiable insertion-ordered set of names lowercased with `Locale.ROOT`, and `rawHeaders()` an unmodifiable list of immutable entries, both built once per request from the adapter's header list. fills: PRD-28 / hole / AMB-3, the request fixes immutability but not the element types
- [D-025] `Response.append(name, value)` SHALL add a header line through the same name and value check as `header`, return the `Response`, and leave `header` with its replace semantics. ← PRD-30

### Trusted proxy predicate

- [D-026] `isFromTrustedProxy()` SHALL return true exactly when `remoteAddress()` follows the forwarding headers for this peer: always under `trustProxyHops(n ≥ 1)` and the legacy `trustProxy(true)`, under `trustProxyCidrs(...)` only when the socket address parses and lies inside a listed CIDR, and false with no trust setting, `trustProxyHops(0)` or an empty CIDR list, through a package-private helper of `ProxyTrustSetting` that both callers share. ← PRD-32

### Abort notification

- [D-027] `Response.onAbort(Runnable listener)` SHALL return `void`, throw `NullPointerException` for a null listener and run a listener registered after the abort immediately. fills: PRD-33 / hole / AMB-4, Runnable mirrors the SPI listener the request moves to the public API
- [D-028] `onAbort` listeners SHALL fire once for a client disconnect detected by the adapter and for `res.abort`, never for a normally completed response, with a listener's `RuntimeException` caught and logged to the app logger so later listeners still run. ← PRD-189

### Relay

- [D-029] `Response.relay(InputStream in, long contentLength)` SHALL keep the `Content-Type` the app set, drop any app-set `Content-Length` and `Transfer-Encoding`, and frame the body only from its length argument. ← PRD-38
- [D-030] `relay` MUST NOT apply the app's `defaultCache` policy. ← PRD-40
- [D-031] The exact-length rule of `relay` (abort when the stream ends early) SHALL apply only when a body is sent; for a HEAD request and a 304 response `relay` keeps a non-negative length as `Content-Length` and sends no body, for a 204 response it sends neither, and in those cases it closes the stream unread. fills: PRD-41 / contradiction / CON-1, a bodyless HEAD or 304 relay with a positive length would otherwise abort
- [D-032] When the stream holds more bytes than a non-negative `contentLength`, `relay` SHALL send exactly `contentLength` bytes, close the stream and finish normally. fills: PRD-41 / hole / AMB-7, the request does not say what happens to surplus bytes
- [D-033] `relay` SHALL throw `IllegalArgumentException` for a length below -1 and close the stream it was given. ← PRD-190
- [D-034] `relay` SHALL copy the body after the handler returns and own the stream exactly as `stream` does. ← PRD-42

### Header value check

- [D-035] `HttpHeaderValues.isFieldValue(String)` SHALL become public as the one value predicate that `DefaultResponse` also uses for its own check. ← PRD-43

### API conventions for request A

- [D-036] Every method added to `Request` or `Response` SHALL be a default method throwing `UnsupportedOperationException`, with `DefaultRequest` and `DefaultResponse` overriding it. ← PRD-268
- [D-037] New public methods MUST NOT carry `@NonNull`; non-null results rely on the package `@NullMarked` default and only nullable positions carry `@Nullable`. fills: PRD-50 / hole / AF-2, the Kotlin rule of this repository bans @NonNull on public API
- [D-038] Every new public method of request A SHALL be exercised by a Kotlin compile-and-run test. ← PRD-50
- [D-039] The API surface tests that pin the method sets of `Request`, `Response` and `RestApp` SHALL be updated to include the new methods. fills: PRD-268 / hole / the surface tests fail on any unlisted method
- [D-040] The `docs/api/` pages for request, response and app SHALL document every request A method with its Express counterpart and Java and Kotlin examples, in Korean and in the English mirror. fills: PRD-27 / hole / the repository rule requires docs for every public API change

## 3. Request B — reverse proxy module

### Module and package

- [D-041] A new Gradle module `NaruServe-proxy` with artifact `naruserve-proxy` SHALL be configured from the root `build.gradle`, depend on `NaruServe-api` only, compile with `release = 8`, join the API 21 animal-sniffer set and be published like the other library modules. ← PRD-145
- [D-042] `NaruServe`, `NaruServe-kotlin` and `NaruServe-android` MUST NOT depend on `NaruServe-proxy`. ← PRD-231
- [D-043] A build check SHALL fail when classes of `NaruServe-proxy` reference the `com.snoworca.naruserve.internal` or `com.snoworca.naruserve.spi` packages. ← PRD-148
- [D-044] The proxy classes SHALL live in package `com.snoworca.naruserve.proxy` with a `package-info.java` carrying `@NullMarked`. ← PRD-51

### API shape

- [D-045] `Proxy` SHALL be a public final class implementing `Middleware` and not `Installable`, created by `Proxy.to(String url)`, whose option methods each return a new immutable instance. ← PRD-44
- [D-046] Option parameters SHALL be typed `int` for `retries` and `maxConcurrent`, `long` for `bodyLimit` and `boolean` for switches, with configured values readable only through package-private accessors used by unit tests. fills: PRD-137 / hole / AMB-25, the request fixes names and ranges but not parameter types
- [D-075] `sslSocketFactory(factory)` SHALL accept a factory on an `http` target and leave it unused there, throwing `NullPointerException` only for a null factory. fills: PRD-136 / hole / AMB-25, call-time validation needs a defined answer for http targets
- [D-047] Time options SHALL take `(long, TimeUnit)` and convert to socket milliseconds by rounding up to at least 1 ms and clamping to `Integer.MAX_VALUE`, while the watchdog keeps nanosecond precision saturated at `Long.MAX_VALUE`. fills: PRD-48 / hole / AMB-22, sub-millisecond values would round to 0, which sockets read as no timeout
- [D-048] `Proxy.to` SHALL accept only an `http` or `https` scheme (case-insensitive), a required ASCII host (name, IPv4 or bracketed IPv6 without zone id), an optional port `1..65535` and an optional base path, rejecting everything else with `IllegalArgumentException`. fills: PRD-46 / hole / AMB-8, the request lists rejected parts but not the accepted grammar
- [D-072] The base path of `Proxy.to`, after its trailing slashes are removed, SHALL pass the same request-target character and path segment checks the proxy applies to request paths, `Proxy.to(null)` throwing `NullPointerException` and any other failure throwing `IllegalArgumentException`. fills: PRD-46 / hole / AMB-8, a base path holding `..` or `%2e` would reopen the traversal the path check closes
- [D-049] `ProxyException` SHALL be a public final class in `com.snoworca.naruserve.proxy` extending `HttpException`, with a nested public enum `ProxyException.Kind` holding the seven kinds of the request, an accessor `kind()`, a status derived from the kind, a null message and the cause kept. fills: PRD-98 / hole / AMB-18, the request names the kinds but not the enum's name or place
- [D-074] `ProxyException` SHALL have exactly one public constructor `ProxyException(ProxyException.Kind kind, @Nullable Throwable cause)`, so apps and tests can build one for `onError` handling. fills: PRD-98 / hole / AMB-18, the constructor shape is public API the request leaves open

### Checks before forwarding

- [D-050] The proxy SHALL apply its checks in this order: WebSocket upgrade passes to `next()`; method token (400); `CONNECT` and `TRACE` matched case-insensitively (405 with `Allow`); request-target characters and path segments (400); header names, values and multiple `Host` (400); body framing (400 or 501); `req.bodyStream(limit)`; concurrency slot (503); watchdog start. fills: PRD-76 / hole / AMB-10 and AMB-11, a request failing several checks needs one defined status
- [D-051] The proxy's own 400, 405 and 501 answers SHALL be thrown into the error flow as plain `HttpException` with a null message, not as `ProxyException`. ← PRD-230
- [D-052] The path check SHALL inspect the full raw `originalUrl()` path and query whatever `stripPrefix` says, while the forwarded target is the base path followed by `url()` when `stripPrefix` is on and by `originalUrl()` otherwise. fills: PRD-54 / hole / AMB-9, the request does not say which path is checked under stripPrefix

### Backend request

- [D-053] The backend request SHALL write `Host` first, then the client headers in received order minus removed ones with the merged `Cookie` at the first `Cookie` position, then `X-Forwarded-For`, `X-Forwarded-Proto` and `X-Forwarded-Host`, then the `.requestHeader` values in option order, then the framing header and `Connection: close`. fills: PRD-58 / hole / AMB-12, the request fixes which headers change but not where they go
- [D-054] `Content-Length` and `Transfer-Encoding` values SHALL be parsed the same way on requests and responses: split on commas, trim optional whitespace, require every `Content-Length` element to be digits that fit in a `long`, and compare elements numerically. fills: PRD-66 / hole / AMB-13, the request does not fix the parsing of list and padded values
- [D-073] `Transfer-Encoding` SHALL be read as the comma-joined list of all its field lines with empty elements ignored and coding names compared case-insensitively, where a coding with parameters (`chunked;x=1`) or an empty overall value counts as a coding other than `chunked` under the request-framing and response-framing tables. fills: PRD-67 / hole / AMB-13, these inputs decide between forwarding and 400, 501 or INVALID_RESPONSE
- [D-055] When no usable socket address exists, the proxy SHALL drop any client `X-Forwarded-For` and send none. fills: PRD-69 / hole / AMB-26
- [D-056] The one-byte pre-read for a request without length headers SHALL run after `req.bodyStream(...)` and before the slot is taken and the watchdog starts. fills: PRD-119 / hole / AMB-23
- [D-057] The copy loop SHALL treat any exception thrown while reading the client body, including the unchecked `HttpException` (413, 408, 400) that the TinyHttpd body stream throws, as a client read failure that closes the backend connection, wrapping only `BodyTooLargeException` into `HttpException(413)`. fills: PRD-100 / defect / the TinyHttpd body stream throws unchecked exceptions from read()

### Backend response

- [D-058] The proxy SHALL validate the framing headers of every response before skipping the body of a HEAD, 204 or 304 response, passing a valid length or -1 to `relay` for HEAD and 304 and -1 for 204. fills: PRD-155 / hole / AMB-14
- [D-059] A three-digit status outside `100..599` SHALL be an `INVALID_RESPONSE`, and a valid status is relayed without the backend reason phrase, which the adapter's standard phrase replaces. fills: PRD-152 / hole / AMB-15
- [D-060] The proxy documentation SHALL state that `Date` and the reason phrase seen by clients come from the gateway adapter. fills: PRD-87 / hole / AMB-16, TinyHttpd writes its own Date
- [D-061] A network-path `Location` (`//authority/...`) SHALL be resolved against the target scheme and rewritten under the same origin and base-path rule as an absolute URL. fills: PRD-92 / hole / AMB-17, leaving it unchanged would leak the backend address

### Errors, timeouts and retries

- [D-062] The proxy SHALL log a `ProxyException` itself only for failures after the response started, leaving earlier failures to the error flow and its logging. fills: PRD-106 / hole / AMB-20
- [D-063] `connectTimeout` SHALL bound the TCP connect and, separately, the TLS handshake as its read timeout, with a slow handshake further bounded by `totalTimeout`. fills: PRD-160 / hole / AMB-21
- [D-064] With retries enabled, every TCP-level connect failure that is neither a connect timeout nor a TLS failure SHALL be retried. fills: PRD-227 / hole / AMB-24, the retry table names two examples of one class

### Concurrency and watchdog

- [D-065] `maxConcurrent` SHALL default to no per-mount limit as the request decides, with the proxy documentation stating that the worker pool (`maxWorkers`, default 64) and `totalTimeout` bound the threads a proxy holds, which keeps `object.md` §14.2's ban on unbounded resource defaults satisfied. ← PRD-249
- [D-066] The JVM-wide lazily created watchdog scheduler SHALL be documented as living outside the app lifecycle, with its idle-thread expiry tested. ← PRD-257

### TLS

- [D-067] Hostname verification SHALL call `SSLParameters.setEndpointIdentificationAlgorithm("HTTPS")` through reflection where it exists and fall back to `HttpsURLConnection.getDefaultHostnameVerifier()`, so the module passes the API 21 signature check without an exemption. ← PRD-164

### Documentation and tests

- [D-068] `docs/api/proxy.md` and its English mirror SHALL document `Proxy`, its options and errors with the Express `http-proxy-middleware` counterpart, Java and Kotlin examples, and every limit and warning the request asks to document. ← PRD-75
- [D-069] Tests of client-disconnect behaviour SHALL run over real TinyHttpd sockets, because the in-memory test adapter never reports an abort. fills: PRD-189 / hole / the in-memory adapter does not notify onAbort
- [D-070] Proxy integration tests SHALL use backends built in test scope from the JDK (`com.sun.net.httpserver` or raw `ServerSocket`), with raw sockets wherever a test needs malformed or delayed responses. fills: PRD-177 / hole / the request fixes the cases but not the test backends
- [D-071] Timing acceptance tests SHALL use short configured values, while the default timeouts are checked through the package-private accessors without waiting. ← PRD-211
