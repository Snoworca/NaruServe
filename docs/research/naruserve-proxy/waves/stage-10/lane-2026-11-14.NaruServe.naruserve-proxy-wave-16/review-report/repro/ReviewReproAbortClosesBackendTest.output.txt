Why it matters: DefaultResponse.abort does not close the input while a copy runs ("a running copy keeps the input and
closes it itself once its read returns"), so when the client goes away while the relay copy is blocked reading a quiet
backend, only the proxy's onAbort listener can close the backend socket. On the mutant the copy thread and backend
connection stay blocked up to readTimeout (60 s default) while the slot is already reported free, so the effective
backend connection count exceeds maxConcurrent.
