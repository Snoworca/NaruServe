## 인수 기준

- [ ] 배열/목록의 대안별 params와 선택 순서를 공통 라우팅 계약에 맞춘다.
- [ ] 정규식 입력은 java.util.regex.Pattern의 문법·플래그·매칭 의미를 사용한다. ECMAScript RegExp 문법·g/y lastIndex·엔진 동등성은 요구하지 않는다.
- [ ] 검색 매칭과 캡처 추출·디코딩 정책을 명시하고 문자열 경로의 자동 case/strict 설정으로 명시적 Pattern 플래그를 덮어쓰지 않는다.
- [ ] Pattern은 공유할 수 있지만 Matcher 실행 상태는 매칭별로 분리하고 실패·비참여 캡처·동시 요청을 검증한다.
- [ ] Java8 및 Android API21에서 사용할 수 있는 캡처 접근/API를 설계하고 Java/Kotlin 오버로드·람다·메서드 참조 호환성을 검증한다.
- [ ] JNI·JavaScript 정규식 엔진·새 ECMAScript parser/VM을 도입하지 않는다. 기존 추가 API와 WebSocket 계약은 유지한다.

## 검증

- path-alternative selection tests
- Java Pattern syntax/flags/captures/matching tests
- Java8 runtime and Android21 API/reference checks
- Java/Kotlin overload and concurrent Matcher isolation tests

## SRS 연결

기존 영향 요구: `IR-HTTP-005`, `IR-HTTP-006`. 구현 전 해당wave의 MCP저작SRS에 연결하고 TDD·요구별증거를 기록한다. 이 이슈 본문은 `docs/spec/`의 대체요구원본이 아니다.

## 사용자 결정

정규식은 Java Pattern을 사용한다. ECMAScript 정규식 엔진·JNI는 범위에서 제외한다. Q-REGEX는 해결되었으며 일반 SRS·TDD 진입 절차를 따른다.
