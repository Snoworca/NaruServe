# Wave 8 duplication audit (stage 8)

Stage 8 merged one lane (d98e9dd..9a2cfd0). Wave 8 adds the Kotlin compatibility checks and tests with the reified Request.body extension of NaruServe-kotlin, the javax Servlet 3.1 adapter (exchange, event stream and pool, configurer, initializer, listener, init parameters) with its Jetty-based tests, the release tooling (gradle/release.gradle, gradle/release-tools, docs/release, README, THIRD-PARTY-LICENSES.md) and the docs/api changes with their docs and build tests. There are forty duplicates after the w8-D-001 revision: nine touch main code or build scripts (w8-D-002 to w8-D-010), thirty-one are test-only (including testFixtures candidates and the docs and build test helpers). Thirty-seven near-misses are recorded as distinct. The recurring blocker for a cross-module merge is the module layout: NaruServe-servlet and NaruServe-tinyhttpd share only NaruServe-api, whose `internal` package is package-private and whose `spi` surface is pinned by HttpAdapterSpiTest and BuildLayoutTest, so duplicated adapter logic stays in each adapter. Two wave-7 precedents are repeated: a literal default that ServerSettings already holds (w7-D-008 became w8-D-001) and the testFixtures request builder (w7-D-014 became w8-D-024).
