## Planned integration boundaries

Use focused internal HttpRouter/HttpLayer/HttpRoute registration and per-request execution/frame types. Public app and mounted Router share registration/execution utilities; no duplicated engine in each class. Keep existing routing.Router/RoutePattern for WS/legacy resolution.

HttpPathPattern.compile(String source, boolean end, boolean caseSensitive, boolean trailing) returns an immutable compiled string matcher. match(rawPath) returns a result with matchedPath(), raw captures() and actual participating wildcard-kind metadata. Scalars are raw singleton captures; wildcard slash splitting occurs before shared strict UTF8 decoding. Public Java Pattern routes retain Java regex semantics.

Keep Request.param(String)/paramInt conveniences; add nullable scalar and immutable list/map access for optional/wildcard values. The observed parameter model retains scalar/list shape (including a one-element wildcard) and absence. Request.rawPath remains original raw pathname for compatibility; path/url/baseUrl/originalUrl are current mount-relative/raw/original views. No eager whole-path decode before matching.

Next keeps run/error and gains Java8/API21 route/router operations, with source-compatible defaults where appropriate. Existing two-argument route handlers remain terminal conveniences; middleware-style three-argument route overloads enable next. New callbacks run through one HTTP execution state without holding locks across user callbacks. Existing legacy ChainNext may remain for WS.

Completion belongs to request execution plus response terminal callbacks, not callback return. Preserve resources until active callbacks and response state permit exactly-once cleanup. Deferred reentry restores lifecycle context. Adapter work starts only after this contract and core tests pass.

The remaining exact public method names and overload ergonomics are routine implementation choices validated by Java/Kotlin compilation tests. No added dependencies or mandatory API24 completion types. Existing conflicting SRS guards are scoped/amended by the host before changing common HTTP behavior; tests must cite the new requirement and never weaken unrelated WS/extension/security evidence.
