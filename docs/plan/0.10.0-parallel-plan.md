# 0.10.0 병렬 구현 계획

이 문서는 실행·배정 계획이다. 요구사항 원본은 `docs/spec/`이며, 동작 구현은 MCP로 등록·갱신한 요구 ID와 인수 기준을 따른다. 최신 사용자 지시가 이전 연구의 승인 대기·배포 제한보다 우선한다.

## 확정 범위

- 에픽 #46과 하위 이슈 #47–#65를 끝까지 처리한다.
- 정규식은 Java `Pattern`을 사용한다. JNI·JavaScript 정규식 엔진은 도입하지 않는다.
- 현재 의존성의 종류·버전·scope를 유지한다. 기존 JUnit, 테스트 fixture, 루트 테스트의 Gson과 기존 개발 환경을 재사용한다.
- Express 5 공통 HTTP 동작을 정합화하고 기존 확장 API와 WebSocket 계약은 보존한다.
- 각 변경은 실패 테스트를 먼저 확인한 뒤 최소 구현·리팩터링·회귀 검증 순서로 수행한다.
- 독립 서브에이전트가 테스트 충분성을 최대 3회 검토한다. 통과한 첫 회차에서 종료하고, 미통과면 테스트·구현 개선 후 재검토한다.
- 모든 기능 후 전체 테스트 충분성을 다시 검토한다. 통과 후 technical-writer로 한영 API 문서를 개선하고 문서 예제·전체 회귀를 재검증한다.
- 사용자 승인 범위에 커밋·푸시, 프로젝트 버전 0.10.0, Maven 배포가 포함된다. 배포 전 산출물 검증은 생략하지 않는다.

## 현재 증거와 제약

- 구현 기준: 274775f; 현재 3f91c6e는 실행 기록만 추가했다. 변경 전 build 기준선은 1,735 tests / 0 failures / 0 skips이며 새 기능 증거가 아니다.
- 기존 SRS는 verified/evolving이다. `FR-ROUTE-003/004/005` 및 `IR-HTTP-005/006`, `FR-APP-003/004`, `CON-BUILD-006`, `FR-REL-005` 등의 충돌을 해당 구현 전에 MCP로 해소한다.
- TinyHttpd는 Maven 3.1.0 고정이다. 실제 JAR socket 실험에서 encoded slash/NUL/dot/malformed 경로가 어댑터 이전에 400으로 거부됐다. 새 의존 API를 전제한 #59/#60은 현재 지시와 충돌하여 사용자에게 전송 계층 경계 허용 여부를 질문했다. 이 국소 질문 때문에 독립 코어·테스트 작업을 멈추지 않는다.
- 이전 연구와 새 실행 입력을 구분한다. 현재 실행 상태와 배정은 이 디렉터리에 저장하고 과거 미해결 JNI 질문은 재사용하지 않는다.

## 파일 소유 경계

- 호스트만 `docs/spec/`을 변경하고 요구 ID를 할당한다. 워커는 SRS 상태·증거를 직접 변경하지 않는다.
- 하네스 워커: 루트의 새 parity 테스트/리소스/도구만 소유한다. `build.gradle` 변경이 필요하면 호스트에 요청한다.
- matcher 워커: 새 engine-free 문자열 패턴 컴파일러와 해당 API 모듈 테스트만 소유한다. 기존 Router/RoutePattern의 WS/legacy 계약과 Dispatcher를 동시에 변경하지 않는다.
- 중앙 통합 소유자: RestApp/RouteBuilder/Request, DefaultRestApp/Dispatcher/ChainNext/DefaultResponse 수명을 순차 통합한다.
- 각 어댑터 워커: 자신의 모듈 main/test만 소유한다. 공통 SPI 변경은 호스트 계약 검토 뒤 합류한다.
- 공유 변환·검증 코드는 기존 common 유틸리티를 재사용하거나 그곳에 단일 구현을 추가한다.
- 구현 워커는 격리된 git worktree에서 명시한 경로만 커밋한다. 호스트는 테스트 결과·차이·의존성 불변을 확인한 뒤 통합한다.
- 사용자 문서 docs/next와 미선택 이미지 등 기존 미추적 파일은 보존하고 커밋에 포함하지 않는다.

## 검증·종결 기준

1. 작업별 요구 ID/AC, 실패 테스트 명령·관찰, green 명령·결과, 변경 SHA를 저장한다.
2. 테스트 검토자는 정상·경계·오류·부작용·회귀를 확인한다. 통과 시 1회로 끝내며 최대 3회 후에도 미흡하면 이슈를 닫지 않는다.
3. 이슈는 실제 구현과 해당 범위 검증이 모두 완료된 뒤 닫는다. 커밋 존재만으로 완료 처리하지 않는다.
4. Java 8 실실행, JDK17, API21 signature/class-reference, Java/Kotlin 예제, 실제 Tiny socket/Servlet 수명, 기존 JSON/body/uploads/static/CORS/services/SSE/WS/shutdown을 검사한다.
5. 새 기능 전체 충분성 통과 후 한영 API 문서를 개선하고 최종 버전·문서·패키지 변경 후 전체 검증을 다시 수행한다.
6. 기존 배포 키/자격증명은 값 노출 없이 재사용한다. TinyHttpd 전용 배포 스크립트는 실행하지 않고 필요한 기존 서명 도구만 임시 작업 공간에서 사용한다.
7. 10개 모듈·50개 기본 산출물과 서명/체크섬 포함 배포 묶음을 검증하고 Central 업로드의 최종 상태 및 원격 Maven 산출물을 확인한다.

## 첫 병렬 배정의 SRS 연결

- 하네스: `OPS-ROUTE-004`, evolving/in_progress, 이슈 #48.
- HTTP 문자열 컴파일러: `FR-ROUTE-018`, evolving/in_progress, 이슈 #49. 기존 WS/legacy matcher를 변경하지 않는 새 파일 경계부터 구현한다.
- 이슈 #47은 전체 코어 계약과 남은 전송 경계까지 해결한 뒤 종결한다. 두 foundation 배정이 전체 이슈 완료를 뜻하지 않는다.
