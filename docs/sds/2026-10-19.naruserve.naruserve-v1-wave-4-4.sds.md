## Acceptance Contracts

- SDS-AC-1 (FR-APP-003 AC-1): WHEN a request reaches the pipeline THE SYSTEM SHALL run all globals in registration order, then all matching prefix middleware in registration order, regardless of interleaved registration between the two lists → `MiddlewarePipeline.run`, `MiddlewarePipeline.addPrefix`
- SDS-AC-2 (FR-APP-003 AC-1): WHEN RouteBuilder.use is called before a verb on the same builder THE SYSTEM SHALL put that middleware, in use order, into that verb's RouteChain; a use after a verb does not reach the earlier verb → `DefaultRouteBuilder.use`, `RouteChain`
- SDS-AC-3 (FR-APP-003 AC-2): WHEN the prefix is "/" or ends with "/" THE SYSTEM SHALL drop trailing empty segments, so "/" covers every path and "/api/" equals "/api"; "/apix" and "/ap" never match "/api" → `PrefixMatcher`, `PrefixMatcher.matches`
- SDS-AC-4 (FR-APP-003 AC-3): WHEN the app policy is caseInsensitive or mergeSlashes THE SYSTEM SHALL compare prefix and path segments after Router.decodeSegments under that same policy → `PrefixMatcher.matches`, `MiddlewarePipeline`
- SDS-AC-5 (FR-APP-003 AC-4): WHEN prefix middleware or a handler reads req.path() THE SYSTEM SHALL return the full decoded path; no prefix stripping exists → `MiddlewarePipeline.run`
- SDS-AC-6 (FR-APP-003 AC-5): WHEN lookup is not MATCHED THE SYSTEM SHALL build the Request with the parsed Method and empty params, run globals and matching prefixes with an empty route list and fallback as terminal → `Dispatcher.handle`, `Dispatcher.fallback`
- SDS-AC-7 (FR-APP-003 AC-7): WHEN preCheck answers THE SYSTEM SHALL return before any DefaultRequest is built, so no middleware, handler or onError runs → `Dispatcher.preCheck`
- SDS-AC-8 (FR-APP-003 AC-8): WHEN the chain runs THE SYSTEM SHALL invoke every step synchronously on the adapter thread that called handle, with no executor → `ChainNext.run`
- SDS-AC-9 (FR-APP-004 AC-1): WHEN one invocation calls run or error a second time THE SYSTEM SHALL throw IllegalStateException without running any step → `ChainNext.run`, `ChainNext.error`
- SDS-AC-10 (FR-APP-004 AC-2): WHEN run is called with the response COMPLETED or ABORTED, or after end() THE SYSTEM SHALL throw IllegalStateException and run no downstream step → `ChainNext.run`, `ChainNext.end`
- SDS-AC-11 (FR-APP-004 AC-3): WHEN next.run() returns THE SYSTEM SHALL have run every downstream step to its end, so a marker after it sees the handler's marker and isCommitted; a downstream exception leaves next.run() unchanged and the Dispatcher hands it to ErrorPath once → `ChainNext.run`, `Dispatcher.handle`
- SDS-AC-12 (FR-APP-004 AC-5): WHEN error(null) is called THE SYSTEM SHALL throw NullPointerException before consuming the continuation → `ChainNext.error`
- SDS-AC-13 (FR-HTTP-021 AC-2): WHEN preCheck runs THE SYSTEM SHALL test, in order, OPTIONS with raw path "*", raw path not starting with "/", PathValidator.isValid, then methodOf(token) == null; Router.lookup is never reached for any of them → `Dispatcher.preCheck`, `Dispatcher.methodOf`
- SDS-AC-14 (FR-HTTP-021 AC-3): WHEN preCheck answers 400 or 501 THE SYSTEM SHALL commit Content-Type application/json; charset=UTF-8, Content-Length of StandardErrors body and the body; a HEAD token keeps the length and writes no bytes → `Dispatcher.automatic`
- SDS-AC-15 (FR-HTTP-022 AC-1): WHEN fallback runs with the response still NEW THE SYSTEM SHALL answer through res with the standard error body, keeping headers middleware set; a non-NEW response is left as is → `Dispatcher.fallback`
- SDS-AC-16 (FR-HTTP-022 AC-3): WHEN fallback answers AUTO_OPTIONS THE SYSTEM SHALL set status 204 and Allow and call res.end(), so no body and no Content-Length header → `Dispatcher.fallback`
- SDS-AC-17 (FR-HTTP-022 AC-4): WHEN the token parses to TRACE or CONNECT and the policy disables it THE SYSTEM SHALL build the Request and answer 501 from fallback after the middleware → `Dispatcher.fallback`, `Dispatcher.methodOf`
- SDS-AC-18 (FR-HTTP-022 AC-6): WHEN lookup is MATCHED with route kind WEBSOCKET THE SYSTEM SHALL run the pipeline with fallback as terminal, giving 426 with Upgrade and Connection headers → `Dispatcher.fallback`
- SDS-AC-19 (FR-HTTP-023 AC-1): WHEN the request is OPTIONS * THE SYSTEM SHALL answer 204 with Allow = allowHeader(Method.any()) and no Content-Length header → `Dispatcher.automatic`, `Dispatcher.allowHeader`

## Durable Rules

- Pre-request rejections are answered before any Request exists — middleware, handlers and onError may assume req.method() and req.path() are valid.
- Exceptions leave next.run() unchanged and reach ErrorPath once from the Dispatcher — middleware can wrap next.run() in try/catch like a Servlet filter.
