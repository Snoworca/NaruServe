## Acceptance Contracts

- SDS-AC-1 (IR-SVL-001 AC-1): WHEN reflection inspects the module THE SYSTEM SHALL find ServletAdapter public final with a public no-argument constructor implementing HttpAdapter, ServletConfigurer a @FunctionalInterface with the one abstract method declared throws Exception, NaruServeInitializer public implementing ServletContainerInitializer, and @NullMarked on the package → `ServletAdapter`, `ServletConfigurer`, `NaruServeInitializer`
- SDS-AC-2 (IR-SVL-001 AC-2): WHEN the module jar named by naruserve.servletJar is read THE SYSTEM SHALL hold the services file whose only line is com.snoworca.naruserve.servlet.NaruServeInitializer → `servletJar`
- SDS-AC-3 (IR-SVL-001 AC-3): WHEN ContainerRule starts a WebAppContext with annotation configuration THE SYSTEM SHALL discover the initializer from the services file and, only with naruserve.configurer, register one servlet named naruserve mapped to /*, async supported, without multipart configuration, while a web application without it registers nothing and answers 404 → `NaruServeInitializer.onStartup`, `ContainerRule`
- SDS-AC-4 (IR-SVL-001 AC-4): WHEN naruserve.urlPattern is /*, / or /api/* THE SYSTEM SHALL map the servlet so; WHEN it is api/*, *.json or empty THE SYSTEM SHALL fail startup with a ServletException naming parameter and value → `InitParams.urlPattern`, `InitParams.prefix`
- SDS-AC-5 (IR-SVL-001 AC-5): WHEN naruserve.shutdownTimeoutSeconds is 1 to 300 or absent (10) THE SYSTEM SHALL return it; WHEN it is 0, 301, ten or empty THE SYSTEM SHALL fail startup with a ServletException naming parameter and value → `InitParams.shutdownSeconds`
- SDS-AC-6 (IR-SVL-001 AC-6): WHEN naruserve.configurer names a missing class, a non-ServletConfigurer, a class without a public no-argument constructor, a configure that throws or a configure that returns null THE SYSTEM SHALL fail startup with a ServletException naming the class, and otherwise pass a Builder already holding a ServletAdapter → `AppStarter.create`
- SDS-AC-7 (IR-SVL-001 AC-7): WHEN a :NaruServe-servlet main class references jakarta/servlet/ THE SYSTEM SHALL fail checkClassReferences naming `Class -> jakarta/servlet/...`, and settings.gradle SHALL include no jakarta module → `classRefPrefixes`
- SDS-AC-8 (CON-SVL-001 AC-1): WHEN the dependency report is read THE SYSTEM SHALL show javax.servlet-api 3.1.0 and javax.websocket-api 1.1 on the servlet compileClasspath only, and NaruServe-api alone on its runtimeClasspath → `ServletBuildTest.servletClasspaths`
- SDS-AC-9 (CON-SVL-001 AC-2): WHEN the dependency rules run THE SYSTEM SHALL find the Jetty 9.4.58.v20250814 artifacts, NaruServe-gson and the api test fixtures only on the servlet test classpaths and no Jetty or Servlet class on the api or an API 21 module classpath → `servletTestDependencies`, `checkDependencyRules`
- SDS-AC-10 (CON-SVL-001 AC-3): WHEN check runs THE SYSTEM SHALL pass the servlet class-reference check, hold no jakarta.servlet module, dependency or reference, no javax/servlet/ reference in an API 21 module and Gson 2.14.0 alone on every classpath → `ServletBuildTest.classReferencesAndGson`, `checkDependencyRules`
- SDS-AC-11 (CON-SVL-001 AC-4): WHEN the build tests run THE SYSTEM SHALL pass the HttpAdapterSpiTest signature comparison unchanged, show no modified file under NaruServe-api spi against the wave 7 merge and a clean TinyHttpd checkout → `ServletBuildTest.spiAndTinyHttpdUntouched`
