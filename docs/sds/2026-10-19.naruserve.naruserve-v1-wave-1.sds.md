## Acceptance Contracts

- SDS-AC-1 (CON-BUILD-002 AC-1): WHEN settings.gradle includes the logger modules THE SYSTEM SHALL name them NaruServe-slf4j, NaruServe-filelog (rotating file) and NaruServe-logcat → `naruModules`
- SDS-AC-2 (CON-BUILD-005 AC-1): WHEN main sources are declared THE SYSTEM SHALL use packages com.snoworca.naruserve (api), .servlet, .tinyhttpd, .gson, .bootstrap, .kotlin, .slf4j, .filelog, .logcat, checked by reading every main source's package line → `naruModules`
- SDS-AC-3 (OPS-BUILD-001 AC-1): WHEN settings.gradle resolves the checkout THE SYSTEM SHALL read providers.gradleProperty('tinyHttpdDir') and fall back to /Users/beom/work/git/TinyHttpd in settings.gradle itself → `tinyHttpdDir`
- SDS-AC-4 (OPS-BUILD-001 AC-3): WHEN the tinyHttpdDir directory is missing THE SYSTEM SHALL throw GradleException "tinyHttpdDir: TinyHttpd checkout not found at <path>" from settings.gradle → `tinyHttpdDir`
- SDS-AC-5 (CON-BUILD-004 AC-3): WHEN Java and Kotlin compile on JDK 17 THE SYSTEM SHALL set sourceCompatibility and targetCompatibility 1.8 beside options.release = 8 for root and all modules → `configureCompile`
- SDS-AC-6 (CON-BUILD-004 AC-1): WHEN the build has compiled THE SYSTEM SHALL have every .class under each module's build/classes main and test outputs at major version 52, read by the root test → `configureCompile`
- SDS-AC-7 (CON-BUILD-011 AC-1): WHEN the nullability library is chosen THE SYSTEM SHALL use org.jspecify:jspecify:1.0.0 in compileOnly of all nine modules and testImplementation for tests, with Kotlin flag -Xjspecify-annotations=strict → `configureDependencies`
- SDS-AC-8 (CON-BUILD-011 AC-2): WHEN a Kotlin test assigns annotatedNullable() to String THE SYSTEM SHALL fail compileTestKotlin, while assigning annotatedNonNull() compiles in the normal build → `annotatedNullable`, `annotatedNonNull`
- SDS-AC-9 (OPS-BUILD-002 AC-2): WHEN Kotlin is configured THE SYSTEM SHALL apply org.jetbrains.kotlin.jvm 2.2.0 to all nine modules and add org.jetbrains.kotlin:kotlin-stdlib:2.2.0 as testImplementation in each, and as api only in NaruServe-kotlin → `configureDependencies`
- SDS-AC-10 (OPS-BUILD-002 AC-3): WHEN ./gradlew build runs THE SYSTEM SHALL execute the Java smoke test in NaruServe-api and the Kotlin smoke test in NaruServe-kotlin → `naruModules`
- SDS-AC-11 (OPS-BUILD-002 AC-4): WHEN build checks need a negative case THE SYSTEM SHALL run it through gradleTestKit() in the root project's test task, using withGradleInstallation(system property naruserve.gradleHome = gradle.gradleHomeDir) and only the targeted task → `BuildChecksTest`
- SDS-AC-12 (CON-BUILD-013 AC-1): WHEN a class is scanned THE SYSTEM SHALL match CONSTANT_Class names and descriptor `L<name>;` entries whose internal name starts with android/, javax/servlet/, jakarta/servlet/, com/google/gson/, com/snoworca/tinyhttpd/ or kotlin/, anchored at the name start → `scanClassRefs`
- SDS-AC-13 (CON-BUILD-013 AC-3): WHEN checkClassReferences runs on an androidModules member THE SYSTEM SHALL scan its main output for javax/servlet/ and fail naming class and reference → `checkClassReferences`
- SDS-AC-14 (CON-BUILD-008 AC-1): WHEN checkClassReferences runs on NaruServe-logcat THE SYSTEM SHALL also scan its main output for android/ and fail on any hit → `checkClassReferences`
- SDS-AC-15 (CON-BUILD-007 AC-3): WHEN checkDependencyRules finds org.jetbrains.kotlin:kotlin-stdlib on runtimeClasspath or compileClasspath of a module other than NaruServe-kotlin THE SYSTEM SHALL fail naming that module path → `checkDependencyRules`
- SDS-AC-16 (CON-BUILD-013 AC-2): WHEN checkDependencyRules resolves compileClasspath, runtimeClasspath, testCompileClasspath and testRuntimeClasspath of every module THE SYSTEM SHALL fail on any com.google.code.gson:gson other than 2.14.0 → `checkDependencyRules`
- SDS-AC-17 (CON-BUILD-009 AC-3): WHEN checkDependencyRules runs THE SYSTEM SHALL fail on any com.snoworca.tinyhttpd component outside NaruServe-tinyhttpd and on tinyhttpd-router or tinyhttpd-session anywhere → `checkDependencyRules`
- SDS-AC-18 (CON-BUILD-012 AC-1): WHEN a NaruServe-gson main class calls java.util.Optional THE SYSTEM SHALL fail animalsnifferMain; NaruServe-servlet and NaruServe-slf4j get no animalsniffer task → `animalsnifferMain`
- SDS-AC-19 (CON-BUILD-010 AC-1): WHEN the root test runs after the build THE SYSTEM SHALL assert `git -C <tinyHttpdDir> status --porcelain` prints nothing → `tinyHttpdDir`
- SDS-AC-20 (OPS-BUILD-003 AC-1): WHEN the TinyHttpd commit is recorded THE SYSTEM SHALL write 46b973e in docs/api/README.md → `naruModules`

## Durable Rules

- Only the root build.gradle configures modules; no module directory holds a build file — keeps one place for compile targets and checks.
- NaruServe-api main classes reference no android, servlet, gson, tinyhttpd or kotlin type — Core must stay portable to API 21 and every adapter.
- TinyHttpd is reached only from NaruServe-tinyhttpd through implementation-scope coordinates — keeps the engine swappable behind HttpAdapter.
