## Acceptance Contracts

- SDS-AC-1 (IR-SSE-001 AC-1): WHEN a Response implementation does not override sse THE SYSTEM SHALL throw UnsupportedOperationException "<class> has no SSE writer", the json and addCookie message form → `sse`
- SDS-AC-2 (IR-SSE-001 AC-3): WHEN SseEvent is reflected THE SYSTEM SHALL find no public constructor and public methods event, id, data and retry only; wire stays package-private → `SseEvent`, `wire`
- SDS-AC-3 (IR-SSE-001 AC-4): WHEN sse is called THE SYSTEM SHALL run requireConfigurable("sse") before the null check and run the configurer on copy(), swapping only after it returned → `DefaultRestApp.sse`, `copy`
- SDS-AC-4 (IR-SSE-001 AC-6): WHEN heartbeatInterval is set THE SYSTEM SHALL convert with unit.toMillis (saturating) and accept 1000..3600000 ms, so 999 MILLISECONDS is refused with the caller's time and unit in the message → `heartbeatInterval`
- SDS-AC-5 (IR-SSE-001 AC-5): WHEN an app never calls sse THE SYSTEM SHALL read heartbeatMillis 15000 and sendQueueSize 262144 from the frozen sseOptions().copy() → `heartbeatMillis`, `sseOptions`
- SDS-AC-6 (FR-SSE-001 AC-1): WHEN sse starts THE SYSTEM SHALL replace any app-set Content-Type and Cache-Control and remove Content-Length and Transfer-Encoding, so each event-stream header appears once, and set status 200 whatever status was set → `DefaultResponse.sse`
- SDS-AC-7 (FR-SSE-001 AC-2): WHEN the state is not NEW THE SYSTEM SHALL throw the notNew IllegalStateException before touching the exchange → `DefaultResponse.sse`
- SDS-AC-8 (FR-SSE-001 AC-1): WHEN ex.eventStream throws a RuntimeException THE SYSTEM SHALL remove the client from the registry, leave the state NEW and rethrow, so the error path commits a 503; an IOException SHALL abort the response and return an ended client → `DefaultResponse.sse`
- SDS-AC-9 (FR-SSE-001 AC-4): WHEN data is encoded THE SYSTEM SHALL split at CRLF first, then lone CR and LF, write "data: " plus each line including empty ones, and end every line with LF → `encode`
- SDS-AC-10 (FR-SSE-001 AC-5): WHEN data is null THE SYSTEM SHALL write the single line "data: ", and retry SHALL be written as the decimal millis only when set (not -1) → `encode`, `retry`
- SDS-AC-11 (FR-SSE-001 AC-6): WHEN event, id, or send(event, data) gets CR, LF or NUL THE SYSTEM SHALL throw from checkField on the calling thread before any queueing; retry below 0 throws IllegalArgumentException "retry must not be negative: <n>" → `checkField`, `id`
- SDS-AC-12 (FR-SSE-001 AC-7): WHEN send(data) is called THE SYSTEM SHALL encode with a null event, so no event line is written → `encode`, `send`
- SDS-AC-13 (FR-SSE-001 AC-9): WHEN an event is queued or written THE SYSTEM SHALL use encode(...).getBytes(UTF_8) → `encode`
- SDS-AC-14 (IR-SSE-001 AC-7): WHEN the Kotlin test runs THE SYSTEM SHALL compile both lambdas with no DSL and find exactly "data: ready\n\n" in the in-memory body → `SseKotlinTest`
