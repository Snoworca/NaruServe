## Acceptance Contracts

- SDS-AC-1 (FR-KT-001 AC-1): WHEN a public package lacks @NullMarked THE SYSTEM SHALL fail naming it, and the test also asserts com.snoworca.naruserve.internal keeps it → `KotlinContractChecks.nullMarkedFailures`
- SDS-AC-2 (FR-KT-001 AC-2): WHEN the table row is nullable THE SYSTEM SHALL require @Nullable on the return type of every value-returning Request overload of that name (attribute(String, Object) is void and skipped), and forbid it for non-nullable rows → `KotlinContractChecks.accessorFailures`, `KotlinAccessorTable.rows`
- SDS-AC-3 (FR-KT-001 AC-3): WHEN the jar types are scanned THE SYSTEM SHALL find no NonNull anywhere, reading ApiJarClasses and not the test class path where NullabilityFixture carries one → `KotlinContractChecks.nonNullFailures`
- SDS-AC-4 (FR-KT-001 AC-4): WHEN fixtures lack NullMarked, @Nullable on a table name, or carry NonNull THE SYSTEM SHALL fail naming the package or Type.method each → `KotlinContractFixtures`
- SDS-AC-5 (FR-KT-001 AC-5): WHEN the api test task runs THE SYSTEM SHALL enumerate by reflection (no method list), pass on the real jar, and need no new Gradle wiring because the test task already sets naruserve.apiJar → `ApiJarClasses.publicTypes`
- SDS-AC-6 (FR-KT-002 AC-1): WHEN a public or protected method is named with one of the ten words THE SYSTEM SHALL fail with `Type.method` → `KotlinContractChecks.keywordFailures`
- SDS-AC-7 (FR-KT-002 AC-2): WHEN the Keywords fixture is checked THE SYSTEM SHALL report exactly ten failures, and SoftNames none → `KotlinContractFixtures`
- SDS-AC-8 (FR-KT-002 AC-3): WHEN the real jar is checked THE SYSTEM SHALL pass, and a Kotlin test calls get, param, status, route and onText style methods without a backtick → `KotlinSurfaceKotlinTest`
- SDS-AC-9 (CON-KT-001 AC-1): WHEN a main class constant pool names kotlinx/coroutines/ THE SYSTEM SHALL fail the check task naming `Class -> kotlinx/coroutines/...`, wired into root check → `checkNoCoroutines`
- SDS-AC-10 (CON-KT-001 AC-2): WHEN a kotlinx-coroutines artifact is resolved on a published module THE SYSTEM SHALL fail naming module and artifact → `checkNoCoroutines`
- SDS-AC-11 (CON-KT-001 AC-3): WHEN the stub class and the POM-only dependency are added to the temp copy THE SYSTEM SHALL fail with the class name and the artifact name in the build output → `BuildChecksTest.checkNoCoroutinesFailsOnClassAndOnArtifact`
- SDS-AC-12 (CON-KT-001 AC-4): WHEN the check is added THE SYSTEM SHALL leave the prefix list and the pinned strings of BuildLayoutTest unchanged, and the pristine build passes with both checks → `checkNoCoroutines`
