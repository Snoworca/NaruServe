### Files

- `NaruServe-tinyhttpd/src/main/java/com/snoworca/naruserve/tinyhttpd/TinyHttpdWebSocket.java` — the TinyHttpd upgrade class; framing from com.snoworca.tinyhttpd.websocket only @req FR-WS-002, FR-WS-005
  - `final class TinyHttpdWebSocket` — one instance per upgrade, built by TinyHttpdExchange.webSocket
    - `TinyHttpdWebSocket(Request req, Response res, WebSocketSettings settings, WebSocketEndpoint endpoint, Runnable onCommitted)` — onCommitted marks the exchange started
    - `run(): void` — handle on the calling worker through CapturingResponse; maps pre-101 TinyHttpd HttpException; returns when the connection ended ← TinyHttpdExchange
    - `static configure(WebSocketHandler h, WebSocketSettings s): WebSocketHandler` — allowAnyOrigin, maxFramePayloadBytes and maxMessageBytes = limit, pingInterval = (int) ms
    - `CapturingResponse` — ResponseWrapper around the TinyHttpd response passed to handle
      - `upgrade(String protocol): UpgradedConnection` — keeps the connection, then runs onCommitted when the response is committed
    - `Listener` — WebSocketListener the factory always returns; bridges onOpen/onText/onBinary/onClose to the endpoint
    - `Channel` — WebSocketChannel over TinyHttpd WebSocket and the captured UpgradedConnection
      - `ping(byte[] payload): void` / `abort(): void` — WebSocket.ping / UpgradedConnection.close()
- `NaruServe-tinyhttpd/src/main/java/com/snoworca/naruserve/tinyhttpd/TinyHttpdExchange.java` — webSocket override outside the exchange lock @req FR-WS-002
  - `TinyHttpdExchange.webSocket(WebSocketSettings settings, WebSocketEndpoint endpoint): void` — requireStartable under the lock, then TinyHttpdWebSocket.run without it
  - `markUpgraded(): void` — sets started under the lock ← TinyHttpdWebSocket
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/WebSocketSender.java` — app-wide sender executor; one write task per session at a time @req FR-WS-005
  - `final class WebSocketSender` — FR-WS-007 adds the queue bound, thread limit and overflow policy; FR-WS-010 adds shutdown
    - `submit(DefaultWebSocketSession session, Runnable write): void` — per-session FIFO; never queues behind another session's write
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultWebSocketSession.java` — ping, close and isOpen of the session @req FR-WS-005
  - `DefaultWebSocketSession.ping(): void` — submit channel.ping(new byte[0]) to the sender slot; dropped when not open
  - `DefaultWebSocketSession.close(int code, String reason): void` — isOpen false at once, records the sent pair, submits channel.close(code, reason)
  - `DefaultWebSocketSession.onClose(int code, String reason): void` — endpoint callback; reports the recorded sent pair when one exists
  - `isOpen(): boolean` — channel open and no close called
- `NaruServe-tinyhttpd/src/test/java/com/snoworca/naruserve/tinyhttpd/RawWebSocketClient.java` — loopback client writing frames by hand @req FR-WS-005
  - `final class RawWebSocketClient` — handshake, masked or unmasked frames, fragments, control frames, reads frames back
    - `frame(boolean fin, int opcode, byte[] payload, boolean masked): void` / `readFrame(): Frame` — 2 s read timeout

## Acceptance Contracts

- SDS-AC-1 (FR-WS-002 AC-6): WHEN run builds the handler THE SYSTEM SHALL call configure(new WebSocketHandler(factory), settings) and then handle(req, capturing) on the calling worker, and the factory SHALL return the one Listener without running user code → `configure`, `run`
- SDS-AC-2 (FR-WS-002 AC-4): WHEN handle throws a TinyHttpd HttpException THE SYSTEM SHALL throw a NaruServe HttpException(getStatus(), getMessage()) with each getHeaders() pair added by withHeader in order → `run`
- SDS-AC-3 (FR-WS-002 AC-5): WHEN that mapping runs and the response is not committed THE SYSTEM SHALL call setHeader("Sec-WebSocket-Accept", null) and setHeader("Sec-WebSocket-Protocol", null) on the wrapped response, which removes both, before throwing → `run`
- SDS-AC-4 (FR-WS-002 AC-8): WHEN the wrapped upgrade returns or throws THE SYSTEM SHALL run onCommitted only if the response is committed, so 413 and 503 leave the exchange unstarted for the error path → `CapturingResponse.upgrade`, `markUpgraded`
- SDS-AC-5 (FR-WS-002 AC-7): WHEN the core aborts an open session THE SYSTEM SHALL call close() on the UpgradedConnection kept by CapturingResponse → `abort`
- SDS-AC-6 (FR-WS-002 AC-9): WHEN an endpoint call inside a Listener callback throws a RuntimeException THE SYSTEM SHALL catch it, abort the channel and return normally to TinyHttpd → `Listener`
- SDS-AC-7 (FR-WS-002 AC-6): WHEN webSocket starts THE SYSTEM SHALL hold the exchange lock only for requireStartable and markUpgraded, never while the read loop runs → `TinyHttpdExchange.webSocket`
- SDS-AC-8 (FR-WS-005 AC-7): WHEN ws.ping() is called on an open session THE SYSTEM SHALL submit channel.ping(new byte[0]) to the session's sender slot → `DefaultWebSocketSession.ping`, `ping`
- SDS-AC-9 (FR-WS-005 AC-8): WHEN ws.close(code, reason) is called THE SYSTEM SHALL make isOpen() false at once, drop later sends, and report the sent (code, reason) to onClose whatever code the client echoed → `DefaultWebSocketSession.close`, `DefaultWebSocketSession.onClose`
- SDS-AC-10 (FR-WS-005 AC-5): WHEN two writes are submitted for one session THE SYSTEM SHALL run them one at a time in submit order on a sender thread → `submit`
- SDS-AC-11 (FR-WS-005 AC-4): WHEN the protocol tests run THE SYSTEM SHALL drive TinyHttpd with RawWebSocketClient frames at maxMessageSize(4096) and read the 1009 close frame code both for one frame and for fragments → `frame`
