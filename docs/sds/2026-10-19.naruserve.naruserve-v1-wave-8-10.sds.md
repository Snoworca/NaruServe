## Interfaces

### Depends

- releaseScan → compileReleaseTools → ReleaseMain → ScanReport → DependencyList
- releaseCheck → releaseScan, releaseLicenses → ReleaseMain → ReleaseGate → ScanReport

### Files

- `build.gradle` — root test source set gets the tools as a source directory, so the default build compiles and tests them @req FR-REL-002, FR-REL-003
  - `releaseToolsSourceDir: sourceSets.test.java.srcDir 'gradle/release-tools'` — unconditional, outside the release guard; no plugin involved
- `gradle/release.gradle` — scan and check tasks; no class of the tools is loaded at configuration time @req FR-REL-002, FR-REL-003
  - `compileReleaseTools` — JavaCompile task, `options.release = 8`, sources gradle/release-tools, output build/release-tools/classes
  - `releaseScan` — dependsOn compileReleaseTools; runs `./gradlew -Prelease -PreleaseScanChild dependencyCheckAggregate` in a child process with ignoreExitValue (OWASP plugin applied by class only when releaseScanChild is set), then JavaExec `ReleaseMain scan-report <exit> <child csv> <graph report> build/reports/naruserve/vulnerability-scan.md`
  - `releaseCheck` — dependsOn releaseScan, releaseLicenses (never the reverse, never from check, build or test); JavaExec `ReleaseMain gate <report> docs/release/vulnerability-exceptions.md`, non-zero exit fails the build
- `gradle/release-tools/com/snoworca/naruserve/release/DependencyList.java` — plain Java 8, java.io only @req FR-REL-002
  - `DependencyList.runtime(List<String> graphLines): SortedSet<String>` — keeps rows `<module>|runtimeClasspath|g:n:v`, drops `com.snoworca.naruserve:` components and keeps `com.snoworca.tinyhttpd`, no duplicates
- `gradle/release-tools/com/snoworca/naruserve/release/ScanReport.java` — report writer and pending decision @req FR-REL-002
  - `enum Cause { NO_NETWORK, MISSING_API_KEY, RATE_LIMIT, TOOL_ERROR }` — written as the `Reason:` token
  - `ScanReport.pending(Cause cause, SortedSet<String> deps): String` — lines `Status: pending`, `Reason: <cause>`, then `## Dependencies`, one `g:n:v` per line
  - `ScanReport.completed(String scannerVersion, String dataTimestamp, List<Finding> findings, SortedSet<String> deps): String` — `Status: completed`, `Scanner:`, `Data timestamp:`, table `| dependency | identifier | CVSS | severity |` or `no findings`, then the dependency list
  - `ScanReport.fromChild(int exit, @Nullable List<Finding> findings, SortedSet<String> deps, String log): String` — exit non-zero or findings null gives pending, cause classified from log (UnknownHost, API key or 403, 429, else TOOL_ERROR)
- `gradle/release-tools/com/snoworca/naruserve/release/ReleaseGate.java` — release block rule @req FR-REL-003
  - `ReleaseGate.decide(String report, String exceptions): Decision` — pass flag and message; High is CVSS 7.0 to 8.9, Critical 9.0 and above; a finding counts only when its dependency is in the report's dependency list; an exception row needs id, dependency, reason, approver and date all non-empty and matches id plus dependency
- `gradle/release-tools/com/snoworca/naruserve/release/ReleaseMain.java` — `main(String[])` dispatching `scan-report`, `gate` (the licenses command is added by FR-REL-004) @req FR-REL-002, FR-REL-003
- `docs/release/vulnerability-scan.md` — copy of the release run's build report, starts with the report format above @req FR-REL-002
  - `vulnerabilityScanRecord` — `Status: pending` with reason, or `completed`
- `docs/release/vulnerability-exceptions.md` — header row `| id | dependency | reason | approver | date |` and `no exceptions` or the rows @req FR-REL-003
  - `vulnerabilityExceptions` — read by ReleaseGate
- `src/test/java/com/snoworca/naruserve/build/ScanReportTest.java` — NEW, no network @req FR-REL-002
  - `class ScanReportTest` — fixtures are dependency-graphs lines and stub exit codes
- `src/test/java/com/snoworca/naruserve/build/ReleaseGateTest.java` — NEW fixture reports and exception tables @req FR-REL-003
  - `class ReleaseGateTest` — one method per case of FR-REL-003 AC-1 and AC-4

## Acceptance Contracts

- SDS-AC-1 (FR-REL-002 AC-1): WHEN a stubbed scan fails for each of the four causes THE SYSTEM SHALL write `Status: pending`, a `Reason:` line naming the cause and a dependency list equal to the sorted union of the nine modules' runtimeClasspath coordinates of dependency-graphs.txt without com.snoworca.naruserve components → `ScanReport.pending`, `DependencyList.runtime`
- SDS-AC-2 (FR-REL-002 AC-2): WHEN a scan finished THE SYSTEM SHALL write `Status: completed`, the scanner version, the data timestamp and the findings table or the sentence `no findings` → `ScanReport.completed`
- SDS-AC-3 (FR-REL-002 AC-3): WHEN the docs test runs THE SYSTEM SHALL find docs/release/vulnerability-scan.md with a Status line, and the T50 vulnerability line of test-results.md `manual-pending` for pending and `verified` for completed → `vulnerabilityScanRecord`
- SDS-AC-4 (FR-REL-002 AC-4): WHEN graph lines hold compileClasspath and test configuration rows (javax.servlet-api, jspecify, junit, jetty) THE SYSTEM SHALL leave them out and keep the tinyhttpd rows → `DependencyList.runtime`
- SDS-AC-5 (FR-REL-002 AC-5): WHEN the child invocation exits non-zero or leaves no findings THE SYSTEM SHALL write the pending report, and a task exit value is never thrown → `ScanReport.fromChild`, `releaseScan`
- SDS-AC-6 (FR-REL-003 AC-1): WHEN fixtures hold a High, a Critical or a Medium finding with no, a complete or an incomplete exception row THE SYSTEM SHALL fail with a message naming id and dependency for High and Critical without a complete exception and pass otherwise → `ReleaseGate.decide`
- SDS-AC-7 (FR-REL-003 AC-2): WHEN the report is pending THE SYSTEM SHALL pass and print `scan pending: release not cleared for T50 vulnerability part`, and release-notes.md SHALL list the scan as pending when vulnerability-scan.md is pending → `ReleaseGate.decide`, `vulnerabilityScanRecord`
- SDS-AC-8 (FR-REL-003 AC-3): WHEN the docs test runs THE SYSTEM SHALL find the exceptions file with the five-column header and the row `no exceptions` or at least one data row → `vulnerabilityExceptions`
- SDS-AC-9 (FR-REL-003 AC-4): WHEN a High finding names a dependency absent from the report's dependency list THE SYSTEM SHALL pass → `ReleaseGate.decide`
- SDS-AC-10 (FR-REL-003 AC-5): WHEN gradle/release.gradle is read as text THE SYSTEM SHALL show releaseCheck depending on releaseScan and releaseLicenses and reading build/reports/naruserve/vulnerability-scan.md, and no check, build or test dependency on it → `releaseCheck`
