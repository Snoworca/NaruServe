  - `final class ErrorPath` — immutable after freeze
    - `ErrorPath(List<ErrorHandler> handlers, SafeLogger logger)` — onError registrations in order, SafeLogger of the app logger (part 8) ← DefaultRestApp, Dispatcher
    - `handle(Throwable error, DefaultRequest req, DefaultResponse res, String requestId): void` — never throws an Exception ← Dispatcher, ChainNext
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/StandardErrors.java` — status table and core-built JSON @req FR-APP-006
  - `public final class StandardErrors` — static only; public because HttpException.code() reads code(int)
    - `code(int status): String` — table of FR-APP-006 AC-2, otherwise "HTTP_" + status
    - `reason(int status): String` — status reason phrase, "Error" for an unknown status
    - `statusOf(Throwable error): int` — HttpException.status(), otherwise 500
    - `messageOf(Throwable error, int status): String` — app-supplied HttpException message, otherwise reason(status); 500 always reason
    - `json(int status, String message, String requestId): byte[]` — UTF-8 {"error":{"code","message","requestId"}}
    - `escape(String s): String` — RFC 8259: quote, backslash, U+0000..U+001F as \b \f \n \r \t or \u00XX
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultResponse.java` — error-time state rule @req FR-APP-005, FR-HTTP-024
  - `public final class DefaultResponse` — existing class
    - `afterFailure(int status, byte[] body, Throwable error): void` — NEW: clear headers, status, JSON Content-Type, send; STREAMING or COMMITTED: abort(error); else no-op ← ErrorPath
    - `afterHandler(): void` — unchanged: NEW ends empty, STREAMING copies ← Dispatcher
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/Dispatcher.java` — failure and unfinished handling @req FR-HTTP-024, FR-HTTP-025
  - `public final class Dispatcher` — existing class
    - `invokeRoute(DefaultRequest req, DefaultResponse res, RouteHandler handler): void` — terminal step: req.decodeQuery(), then the handler ← MiddlewarePipeline
    - `finish(DefaultRequest req, DefaultResponse res): void` — after the pipeline returned: warn when NEW, then afterHandler ← Dispatcher
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultRequest.java` — query decoding failure as HttpException @req FR-HTTP-025
  - `public final class DefaultRequest` — existing class
    - `decodeQuery(): void` — HttpException(400) without message for bad %XX or invalid UTF-8; not cached, every call rethrows a new one
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultRestApp.java` — onError registration @req FR-APP-005
  - `onError(ErrorHandler h): RestApp` — requireConfigurable, appended in order; ErrorPath built at freeze

## Acceptance Contracts

- SDS-AC-1 (FR-APP-005 AC-1): WHEN a step throws an Exception or calls next.error(e) THE SYSTEM SHALL call ErrorPath.handle once with that same instance; a thrown java.lang.Error is not routed, it aborts the response and is rethrown as in wave 3 → `ErrorPath.handle`
- SDS-AC-2 (FR-APP-005 AC-3): WHEN an onError handler returns THE SYSTEM SHALL call the next one only while res.state() is NEW; the chain runs whatever the state was on arrival → `ErrorPath.handle`
- SDS-AC-3 (FR-APP-005 AC-4): WHEN the chain ends with the response NEW THE SYSTEM SHALL call afterFailure(statusOf(e), json(...), e), dropping status and headers the app set → `ErrorPath.handle`, `DefaultResponse.afterFailure`
- SDS-AC-4 (FR-APP-005 AC-5): WHEN an onError handler throws THE SYSTEM SHALL log the thrown exception at ERROR, stop the chain and answer the standard 500 if still NEW → `ErrorPath.handle`
- SDS-AC-5 (FR-APP-005 AC-6): WHEN the error arrives with the response STREAMING or COMMITTED THE SYSTEM SHALL abort after the chain; COMPLETED and ABORTED stay unchanged → `DefaultResponse.afterFailure`
- SDS-AC-6 (FR-APP-005 AC-8): WHEN statusOf(e) is 500 THE SYSTEM SHALL log e once at ERROR with its Throwable through the app logger whatever the response state; any other status is not logged at ERROR → `ErrorPath.handle`, `StandardErrors.statusOf`
- SDS-AC-7 (FR-APP-005 AC-9): WHEN the error path picks the outcome THE SYSTEM SHALL read res.state() once after the onError chain under the DefaultResponse lock; a response committed on arrival can only stay committed or end, so this equals the arrival-state rule → `DefaultResponse.afterFailure`
- SDS-AC-8 (FR-APP-006 AC-1): WHEN json builds a body THE SYSTEM SHALL emit exactly {"error":{"code":"<c>","message":"<m>","requestId":"<id>"}} with no whitespace, no exception class and no stack frame → `StandardErrors.json`
- SDS-AC-9 (FR-APP-006 AC-2): WHEN code maps a status THE SYSTEM SHALL return 400 BAD_REQUEST, 404 NOT_FOUND, 405 METHOD_NOT_ALLOWED, 413 PAYLOAD_TOO_LARGE, 415 UNSUPPORTED_MEDIA_TYPE, 422 UNPROCESSABLE_ENTITY, 426 UPGRADE_REQUIRED, 500 INTERNAL_ERROR, 501 NOT_IMPLEMENTED, 503 SERVICE_UNAVAILABLE, else HTTP_<status> → `StandardErrors.code`
- SDS-AC-10 (FR-APP-006 AC-3): WHEN the error is an HttpException created with a message and its status is not 500 THE SYSTEM SHALL use that message; every other case uses the reason phrase → `StandardErrors.messageOf`, `StandardErrors.reason`
- SDS-AC-11 (FR-APP-006 AC-6): WHEN the request is HEAD THE SYSTEM SHALL send Content-Type and the Content-Length of the JSON with zero body bytes through DefaultResponse.bodyless → `DefaultResponse.afterFailure`
- SDS-AC-12 (FR-APP-006 AC-7): WHEN a standard body is written THE SYSTEM SHALL use the requestId passed by the Dispatcher, the same value the access log line uses → `StandardErrors.json`, `ErrorPath.handle`
- SDS-AC-13 (FR-APP-006 AC-8): WHEN the message has a quote, backslash or control character THE SYSTEM SHALL escape it per RFC 8259 without the app JsonCodec; non-ASCII stays literal UTF-8 → `StandardErrors.escape`
- SDS-AC-14 (FR-HTTP-024 AC-2): WHEN a checked exception escapes after status(201) and header X-A THE SYSTEM SHALL answer 500 with only the standard headers and not rethrow to the adapter → `ErrorPath.handle`, `DefaultResponse.afterFailure`
- SDS-AC-15 (FR-HTTP-024 AC-4): WHEN the pipeline returns with the response NEW and no error path ran THE SYSTEM SHALL log one warn naming method and path, then end with the status and headers set so far; STREAMING copies with no warn → `Dispatcher.finish`
- SDS-AC-16 (FR-HTTP-025 AC-3): WHEN the matched route's middleware finished THE SYSTEM SHALL call decodeQuery before the handler, so the HttpException(400) reaches ErrorPath and onError; a middleware reading req.query gets it earlier → `Dispatcher.invokeRoute`, `DefaultRequest.decodeQuery`
- SDS-AC-17 (FR-HTTP-025 AC-2): WHEN a pair has no "=" or an empty name THE SYSTEM SHALL keep it with value "" and decode "+" as space in names and values, as wave 3 does → `DefaultRequest.decodeQuery`

## Durable Rules

- Only the core writes the standard error JSON, never through JsonCodec — the error body must stay correct when the app codec is broken.
- The error outcome is decided by the response state after the onError chain — committed responses are aborted, never given a second status line.
