## Acceptance Contracts

- SDS-AC-1 (IR-APP-004 AC-2): WHEN get misses THE SYSTEM SHALL throw ServiceNotFoundException whose message contains the type's binary name, while getOrNull returns null and contains false → `ServiceNotFoundException`, `ServiceRegistry.get`
- SDS-AC-2 (IR-APP-004 AC-3): WHEN Request is reflected THE SYSTEM SHALL find application and service plus every wave 3 method; the IR-HTTP-001 AC-3 surface test is re-pointed → `Request.application`, `Request.service`
- SDS-AC-3 (IR-APP-004 AC-4): WHEN attribute(key, v) gets a typed null THE SYSTEM SHALL remove the key; null keys, types and register arguments throw NullPointerException → `ApplicationContext.attribute`, `ServiceRegistry.register`
- SDS-AC-4 (IR-APP-004 AC-5): WHEN Kotlin calls req.service(T::class.java) THE SYSTEM SHALL yield a non-null type because only getOrNull and the attribute read are @Nullable → `Request.service`, `ServiceRegistry.getOrNull`
- SDS-AC-5 (IR-APP-005 AC-3): WHEN ServerHandle is reflected THE SYSTEM SHALL find exactly port, address and state, address being 127.0.0.1 → `ServerHandle`, `AppState`
- SDS-AC-6 (IR-APP-005 AC-4): WHEN listen gets a port outside 0..65535 or shutdown a negative timeout or null unit THE SYSTEM SHALL throw IllegalArgumentException or NullPointerException before any state change → `RestApp.listen`, `RestApp.shutdown`
- SDS-AC-7 (IR-APP-005 AC-5): WHEN AppStartException is reflected THE SYSTEM SHALL find a RuntimeException subclass with a (String, Throwable) constructor → `AppStartException`
- SDS-AC-8 (IR-APP-005 AC-6): WHEN Kotlin runs onStart, listen(0), port(), state() and shutdown THE SYSTEM SHALL compile without DSL over the in-memory adapter → `RestApp.onStart`, `LifecycleCallback`, `RestApp.state`
- SDS-AC-9 (IR-APP-006 AC-2): WHEN a record passes the threshold THE SYSTEM SHALL print one line <timestamp> <LEVEL> <message> with yyyy-MM-dd'T'HH:mm:ss.SSSZ to System.out for TRACE..INFO or System.err for WARN, ERROR, reading System.out and System.err at write time → `ConsoleLogger.format`, `Logger`, `LogLevel`
- SDS-AC-10 (IR-APP-006 AC-3): WHEN close or flush runs THE SYSTEM SHALL flush both streams and leave them open → `ConsoleLogger.close`, `ConsoleLogger.flush`
- SDS-AC-11 (IR-APP-006 AC-4): WHEN logger(null) is called THE SYSTEM SHALL throw NullPointerException; logger() reads in any state → `RestApp.logger`
- SDS-AC-12 (IR-APP-007 AC-2): WHEN no accessLog call was made THE SYSTEM SHALL hold enabled, INFO, all includes and no exclude; repeated calls mutate the one object in order → `DefaultAccessLogOptions`, `RestApp.accessLog`
- SDS-AC-13 (IR-APP-007 AC-3): WHEN accessLog, level or exclude gets null THE SYSTEM SHALL throw NullPointerException → `RestApp.accessLog`, `AccessLogOptions`
- SDS-AC-14 (IR-APP-007 AC-4): WHEN Kotlin calls app.accessLog { it.exclude("/health") } THE SYSTEM SHALL compile via the @FunctionalInterface Configurer → `Configurer`
