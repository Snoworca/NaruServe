## Interfaces

### Depends

- DefaultRestApp → WebSocketUpgrade → WebSocketSender, WebSocketIdleScheduler
- DefaultWebSocketSession → WebSocketSender, WebSocketIdleScheduler → WebSocketChannel

### Files

- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/WebSocketSender.java` — per-session byte-bounded queues drained on one ThreadPoolExecutor @req FR-WS-007
  - `WebSocketSender(int maxThreads, IntSupplier port, SafeLogger log)` — maxThreads = maxUpgradedConnections of the app's server options at freeze ← DefaultRestApp
  - `queue(DefaultWebSocketSession session, Runnable write, int bytes, int limit): boolean` — false on overflow, with the message dropped and the queue emptied
  - `last(DefaultWebSocketSession session, Runnable close): void` — discards queued writes, appends close as the final task; later queue calls return false
  - `idle(DefaultWebSocketSession session): boolean` — no write of the session running or queued
  - `awaitIdle(DefaultWebSocketSession session): void` — discards queued writes, then blocks until the running one returned
  - `release(DefaultWebSocketSession session): void` — drops the session's slot and anything still queued
  - `queuedBytes(DefaultWebSocketSession session): int` / `slots(): int` / `executor(): ThreadPoolExecutor` — read by tests
  - `keepAlive(long millis): void` — internal test hook; default 60000
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/WebSocketIdleScheduler.java` — one scheduler thread for idle checks of one app @req FR-WS-008
  - `WebSocketIdleScheduler(IntSupplier port, SafeLogger log)` — ScheduledThreadPoolExecutor(1), remove-on-cancel; thread created on first schedule
  - `watch(DefaultWebSocketSession session, long idleMillis): void` / `unwatch(DefaultWebSocketSession session): void` — called from onOpen and onClose
  - `check(DefaultWebSocketSession session): void` — closeBy(1001, "idle timeout") once idle, else reschedules at the remaining time
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultWebSocketSession.java` — byte counting, activity clock, overflow and close-time release @req FR-WS-007, FR-WS-008
  - `touch(): void` / `lastActivityNanos(): long` — activity clock read by check
  - `abort(): void` — channel.abort() when a channel is set ← WebSocketIdleScheduler
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/WebSocketUpgrade.java` — sender-slot wait before the exchange finishes @req FR-WS-007
  - `WebSocketUpgrade.run(HttpExchange ex, DefaultRequest req, DefaultResponse res, @Nullable WebSocketHandler handler, String rid): void` — awaitIdle(session) after ex.webSocket returned or threw after open, then res.upgraded()
- `NaruServe-api/src/main/java/com/snoworca/naruserve/WebSocketOptions.java` — no pong-timeout or handshake-timeout setter in v1 @req FR-WS-008
  - `public interface WebSocketOptions` — five setters only, as IR-WS-001 fixed

## Acceptance Contracts

- SDS-AC-1 (FR-WS-007 AC-1): WHEN a message is queued THE SYSTEM SHALL count text as getBytes(UTF_8).length, binary as the array length and sendJson as its encoded text, ping and close as 0, and release the bytes when that write returns, so the in-flight message stays counted → `queue`, `queuedBytes`
- SDS-AC-2 (FR-WS-007 AC-6): WHEN queuedBytes + bytes > sendQueueSize THE SYSTEM SHALL return false from queue and the session SHALL call closeBy(1008, "send queue overflow") and return normally; a message alone above the limit overflows an empty queue → `queue`, `last`
- SDS-AC-3 (FR-WS-007 AC-2): WHEN the sender is built THE SYSTEM SHALL use ThreadPoolExecutor(max, max, keep-alive, LinkedBlockingQueue) with allowCoreThreadTimeOut(true), daemon threads of 256 KiB stack named naruserve-<port>-ws-sender-<n> with port.getAsInt() read in newThread → `WebSocketSender`, `executor`
- SDS-AC-4 (FR-WS-007 AC-2): WHEN keepAlive(200) is set THE SYSTEM SHALL call setKeepAliveTime on the executor so idle threads end after 200 ms → `keepAlive`
- SDS-AC-5 (FR-WS-007 AC-3): WHEN a session has queued writes and none running THE SYSTEM SHALL submit one drain task that polls that session's queue until empty, each write one whole channel call; a second session gets its own drain task and thread → `queue`
- SDS-AC-6 (FR-WS-007 AC-7): WHEN onClose ran THE SYSTEM SHALL call release, so slots() and the registry size return to their previous value and the attribute map is empty → `release`, `slots`
- SDS-AC-7 (FR-WS-007 AC-8): WHEN ex.webSocket returns, or throws after open, THE SYSTEM SHALL run awaitIdle(session) without a time bound in run before res.upgraded(), never in TinyHttpdWebSocket or onClose → `WebSocketUpgrade.run`, `awaitIdle`
- SDS-AC-8 (FR-WS-008 AC-1): WHEN a session opens THE SYSTEM SHALL schedule only idle and abort checks, no ping task, leaving pings to TinyHttpd's read loop → `watch`
- SDS-AC-9 (FR-WS-008 AC-3): WHEN the options types are read by reflection THE SYSTEM SHALL find no method of WebSocketOptions or ServerOptions whose name contains "pong" or "handshake" ignoring case → `WebSocketOptions`
- SDS-AC-10 (FR-WS-008 AC-6): WHEN onText or onBinary runs, or a text or binary write returns, THE SYSTEM SHALL call touch(); pings, pongs and close frames do not touch → `touch`
- SDS-AC-11 (FR-WS-008 AC-4): WHEN check runs and nanoTime - lastActivityNanos >= idleTimeout THE SYSTEM SHALL call closeBy(1001, "idle timeout") and schedule one abort check 1000 ms later → `check`, `lastActivityNanos`
- SDS-AC-12 (FR-WS-008 AC-5): WHEN the abort check runs and idle(session) is false THE SYSTEM SHALL call abort(); the scheduler thread SHALL call no WebSocketChannel write method, and its thread is a daemon of 256 KiB stack named naruserve-<port>-ws-idle → `abort`, `WebSocketIdleScheduler`
