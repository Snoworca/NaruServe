## Acceptance Contracts

- SDS-AC-1 (FR-APP-010 AC-1): WHEN an onStart throws an unchecked exception THE SYSTEM SHALL rethrow the same instance and never call bind → `DefaultRestApp.failStart`, `DefaultRestApp.listen`
- SDS-AC-2 (FR-APP-010 AC-2): WHEN the cause is checked (IOException) THE SYSTEM SHALL throw AppStartException with that cause → `DefaultRestApp.failStart`
- SDS-AC-3 (FR-APP-010 AC-3): WHEN bind throws IOException THE SYSTEM SHALL call adapter.stop then adapter.release before throwing AppStartException → `DefaultRestApp.listen`
- SDS-AC-4 (FR-APP-010 AC-4): WHEN a start fails THE SYSTEM SHALL call fail() before closing owned and registered resources in reverse order, then terminate() → `AppLifecycle.fail`, `DefaultRestApp.listen`
- SDS-AC-5 (FR-APP-010 AC-5): WHEN any start failure happens THE SYSTEM SHALL run no onStop callback → `DefaultRestApp.listen`
- SDS-AC-6 (FR-APP-010 AC-6): WHEN the start fails THE SYSTEM SHALL flushAndClose the app logger once as the last step before TERMINATED, skipping it at its owned position → `DefaultRestApp.listen`
- SDS-AC-7 (FR-APP-011 AC-1): WHEN the sequence runs THE SYSTEM SHALL do BEFORE_WAIT, adapter.stop, FORCE_CLOSE, onStop, AFTER_ON_STOP, owned close reverse, logger flush and close, adapter.release, TERMINATED → `DefaultRestApp.runShutdownSequence`
- SDS-AC-8 (FR-APP-011 AC-2): WHEN shutdown begins THE SYSTEM SHALL compute deadline = System.nanoTime() + unit.toNanos(timeout) once and pass max(0, deadline - now) in nanoseconds to adapter.stop → `DefaultRestApp.runShutdownSequence`
- SDS-AC-9 (FR-APP-011 AC-3): WHEN a participant throws THE SYSTEM SHALL log it at ERROR and run the next participant → `ShutdownParticipants.run`, `ShutdownParticipants.add`
- SDS-AC-10 (FR-APP-011 AC-4): WHEN onStop runs THE SYSTEM SHALL still resolve onStart-registered services through ctx.get; no resource is closed yet → `DefaultRestApp.runShutdownSequence`
- SDS-AC-11 (FR-APP-011 AC-5): WHEN two threads call shutdown on RUNNING THE SYSTEM SHALL run the sequence only in the beginStop winner; the loser waits via awaitTerminated up to its timeout and returns → `AppLifecycle.beginStop`, `AppLifecycle.awaitTerminated`
- SDS-AC-12 (FR-APP-011 AC-6): WHEN a request is in flight at shutdown THE SYSTEM SHALL let it complete while adapter.stop waits within the deadline → `DefaultRestApp.runShutdownSequence`
- SDS-AC-13 (FR-APP-011 AC-7): WHEN the app logger is also owned THE SYSTEM SHALL skip it in the owned close and close it once at the logger step; ConsoleLogger.close leaves System.out open → `DefaultRestApp.runShutdownSequence`
- SDS-AC-14 (FR-APP-011 AC-8): WHEN an onStop callback throws THE SYSTEM SHALL log at ERROR, run the remaining onStop callbacks and continue to TERMINATED → `DefaultRestApp.runShutdownSequence`
- SDS-AC-15 (FR-APP-012 AC-1): WHEN shutdown runs in NEW THE SYSTEM SHALL compareAndSet NEW→TERMINATED, flushAndClose the logger once, run no callback and no bind → `DefaultRestApp.shutdown`
- SDS-AC-16 (FR-APP-012 AC-2): WHEN shutdown runs in STARTING THE SYSTEM SHALL requestPendingStop and awaitTerminated; listen skips later onStart callbacks, skips bind, and throws AppStartException "shutdown was requested while starting" → `AppLifecycle.requestPendingStop`, `DefaultRestApp.listen`
- SDS-AC-17 (FR-APP-012 AC-3): WHEN the pending stop is seen after bind THE SYSTEM SHALL call stop and release, never set RUNNING, and the gate answers held requests 503 → `AppLifecycle.pendingStop`, `GatedExchangeHandler.handle`
- SDS-AC-18 (FR-APP-012 AC-4): WHEN awaitTerminated times out THE SYSTEM SHALL return from shutdown normally without exception → `AppLifecycle.awaitTerminated`, `DefaultRestApp.shutdown`
- SDS-AC-19 (FR-APP-012 AC-5): WHEN shutdown runs in FAILED THE SYSTEM SHALL wait via awaitTerminated up to the timeout; in TERMINATED it returns at once → `DefaultRestApp.shutdown`, `AppLifecycle.terminate`
- SDS-AC-20 (FR-APP-012 AC-6): WHEN listen runs in TERMINATED THE SYSTEM SHALL throw IllegalStateException → `DefaultRestApp.listen`
- SDS-AC-21 (FR-APP-013 AC-1): WHEN a request reaches the gated handler in STOPPING THE SYSTEM SHALL answer 503, Connection: close and code SERVICE_UNAVAILABLE → `GatedExchangeHandler.handle`
- SDS-AC-22 (FR-APP-013 AC-2): WHEN the gate answers THE SYSTEM SHALL run no middleware, handler or onError and write exactly one access-log line with 503 → `GatedExchangeHandler.handle`
- SDS-AC-23 (FR-APP-013 AC-3): WHEN a request passed the gate before STOPPING THE SYSTEM SHALL let it complete with its handler response; the gate reads state once at entry → `GatedExchangeHandler.handle`
- SDS-AC-24 (FR-APP-013 AC-4): WHEN OPTIONS *, an unknown method token or a raw path without leading / arrives THE SYSTEM SHALL apply the gate before the dispatcher pre-request checks → `GatedExchangeHandler.handle`
