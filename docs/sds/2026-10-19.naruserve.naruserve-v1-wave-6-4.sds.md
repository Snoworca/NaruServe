## Interfaces

### Files

- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/SpoolingBuffer.java` — memory up to memoryThreshold, then one temp file @req FR-MULTIPART-004
  - `final class SpoolingBuffer extends OutputStream` — text parts never spool
    - `toUpload(String name, @Nullable String filename, @Nullable String contentType): DefaultUploadFile` ← MultipartParser
    - `discard(): void` — deletes a half-written temp file ← MultipartParser
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/SpoolRegistry.java` — per-app set of open temp files @req FR-MULTIPART-004, FR-MULTIPART-006
  - `final class SpoolRegistry` — one per DefaultRestApp; no static state
    - `createTemp(File dir): File` — File.createTempFile("naru-upload-", ".tmp", dir); HttpException(500) once closed
    - `forget(File f): void` / `closeAndDeleteAll(): void` — deletes open files then refuses new ones
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultUploadFile.java` — in-memory or spooled part @req FR-MULTIPART-004, FR-MULTIPART-005
  - `final class DefaultUploadFile implements UploadFile` — filename kept verbatim, never used in a path
    - `static final long BYTES_LIMIT = 8388608`
    - `save(File destination): void` — FileOutputStream copy (truncates), then temp deleted and content released
    - `transferTo(OutputStream target): void` — copies, flushes, never closes target
    - `bytes(): byte[]` — IllegalStateException naming size and limit above BYTES_LIMIT
    - `close(): void` / `release(): void` — releases content; release also marks the request ended ← DefaultRequest
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultRequest.java` — releases the uploads of its parse @req FR-MULTIPART-006
  - `releaseUploads(): void` — release() on every cached part; idempotent ← Dispatcher
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/Dispatcher.java` — request end triggers releaseUploads @req FR-MULTIPART-006
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultRestApp.java` — owns the SpoolRegistry and its AFTER_ON_STOP participant @req FR-MULTIPART-006
  - `spool(): SpoolRegistry` ← Dispatcher

## Acceptance Contracts

- SDS-AC-1 (FR-MULTIPART-004 AC-1): WHEN byte memoryThreshold+1 of a file part arrives THE SYSTEM SHALL create the temp file, flush the buffered bytes to it and drop the buffer → `SpoolingBuffer`
- SDS-AC-2 (FR-MULTIPART-004 AC-3): WHEN a temp file is created THE SYSTEM SHALL pass only the fixed prefix, suffix and tempDirectory, never a client-derived value → `createTemp`
- SDS-AC-3 (FR-MULTIPART-005 AC-1): WHEN save runs on a spooled part THE SYSTEM SHALL copy through a truncating FileOutputStream and then delete the temp file, never File.renameTo, so behaviour is the same across file systems → `save`
- SDS-AC-4 (FR-MULTIPART-005 AC-4): WHEN the request ends THE SYSTEM SHALL close every InputStream that inputStream() handed out, so a later read throws IOException, and content methods SHALL throw IllegalStateException → `release`
- SDS-AC-5 (FR-MULTIPART-005 AC-5): WHEN close() is called before the request ended THE SYSTEM SHALL release the content like save, and later content methods SHALL throw IllegalStateException → `DefaultUploadFile.close`
- SDS-AC-6 (FR-MULTIPART-006 AC-1): WHEN the response's done callback fires (complete or abort) or the error path returned THE SYSTEM SHALL call releaseUploads once; a parse failure, including a mid-upload IOException, SHALL discard its temp files before rethrowing → `releaseUploads`, `discard`
- SDS-AC-7 (FR-MULTIPART-006 AC-3): WHEN createTemp runs after closeAndDeleteAll THE SYSTEM SHALL throw HttpException(500) and create no file → `createTemp`, `closeAndDeleteAll`
- SDS-AC-8 (FR-MULTIPART-006 AC-2): WHEN the app is constructed THE SYSTEM SHALL add closeAndDeleteAll as one ShutdownParticipants AFTER_ON_STOP participant → `spool`
