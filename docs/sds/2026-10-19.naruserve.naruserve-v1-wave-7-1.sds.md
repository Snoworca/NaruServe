## Interfaces

### Depends

### Files

- `NaruServe-api/src/main/java/com/snoworca/naruserve/spi/WebSocketEndpoint.java` — core-owned WebSocket callbacks; no adapter implements it @req IR-WS-002
  - `public interface WebSocketEndpoint` — not @FunctionalInterface; no method declares a checked exception; the core never throws from it
    - `onOpen(WebSocketChannel channel): void` / `onText(String text): void` / `onBinary(byte[] data): void` / `onClose(int code, String reason): void` — called on the adapter's read thread, one at a time
- `NaruServe-api/src/main/java/com/snoworca/naruserve/spi/WebSocketChannel.java` — adapter-owned framed connection the core writes to @req IR-WS-002
  - `public interface WebSocketChannel` — implemented by each adapter; RFC 6455 framing stays in the adapter's engine
    - `sendText(String text): void` / `sendBinary(byte[] data): void` / `ping(byte[] payload): void` — throw IOException; called only from the session's sender slot
    - `close(int code, String reason): void` / `abort(): void` / `isOpen(): boolean` — no checked exception; abort closes the socket with no close frame
- `NaruServe-api/src/main/java/com/snoworca/naruserve/spi/WebSocketSettings.java` — immutable adapter-facing WebSocket settings @req IR-WS-002
  - `public final class WebSocketSettings` — getter-only value built by the core from the frozen WebSocketOptions
    - `WebSocketSettings(int maxMessageBytes, long pingIntervalMillis)` — public constructor; values already range-checked by the core
    - `maxMessageBytes(): int` / `pingIntervalMillis(): long` — read by the adapter at upgrade time
- `NaruServe-api/src/main/java/com/snoworca/naruserve/spi/HttpExchange.java` — gains one default method; requirement comments re-pointed to IR-HTTP-007 @req IR-HTTP-007, IR-WS-002
  - `default void webSocket(WebSocketSettings settings, WebSocketEndpoint endpoint) throws IOException` — UOE unless overridden; returns after the connection closed
- `NaruServe-api/src/main/java/com/snoworca/naruserve/spi/StreamDrain.java` — gains the add-only SSE hand-over; stays @FunctionalInterface @req IR-HTTP-007
  - `default void attach(OutputStream out)` — does nothing; every adapter's eventStream calls it with the body stream before it returns
- `NaruServe-api/src/main/java/com/snoworca/naruserve/spi/HttpAdapter.java` — requirement comments re-pointed to IR-HTTP-007, no signature change @req IR-HTTP-007
- `NaruServe-api/src/main/java/com/snoworca/naruserve/spi/UpgradeHandler.java` — requirement comments re-pointed to IR-HTTP-007, raw upgrade kept as is @req IR-HTTP-007
- `NaruServe-api/src/testFixtures/java/com/snoworca/naruserve/testing/InMemoryHttpAdapter.java` — exchange overrides webSocket; eventStream attaches the drain @req IR-WS-002, IR-HTTP-007
  - `refuseWebSocket(@Nullable HttpException e): void` — every later webSocket call throws e before 101; null restores accepting
  - `nextChannel(long timeout, TimeUnit unit): InMemoryWebSocketChannel` — the next channel opened, or AssertionError after timeout
  - `Exchange.webSocket(WebSocketSettings settings, WebSocketEndpoint endpoint)` — records 101, opens a channel, runs its read loop until closed
  - `Exchange.eventStream(int status, List<Map.Entry<String, String>> headers, StreamDrain drain)` — commits, calls drain.attach(body) and only then starts the worker
- `NaruServe-api/src/testFixtures/java/com/snoworca/naruserve/testing/InMemoryWebSocketChannel.java` — in-memory WebSocketChannel plus the test-side peer @req IR-WS-002
  - `public final class InMemoryWebSocketChannel implements WebSocketChannel` — records every call; exchange thread is the read thread
    - `settings(): WebSocketSettings` / `sent(): List<Object>` / `pings(): int` / `closeCode(): int` / `closeReason(): String` / `aborted(): boolean` — what the core wrote, in call order
    - `clientText(String text): void` / `clientBinary(byte[] data): void` / `clientClose(int code, String reason): void` — queue a peer event for the read loop
    - `close(int code, String reason): void` / `abort(): void` — end the read loop, peer echo or 1006

## Acceptance Contracts

- SDS-AC-1 (IR-HTTP-007 AC-4): WHEN the SPI signature test runs THE SYSTEM SHALL compare reflection against a literal list of `Type.method(params)->return` strings copied from 9ce5cc4 for the nine types, require every entry, and require the added set to be exactly HttpExchange.webSocket and StreamDrain.attach → `webSocket`, `attach`
- SDS-AC-2 (IR-HTTP-007 AC-4): WHEN StreamDrain is read by reflection THE SYSTEM SHALL find @FunctionalInterface, drain(OutputStream) its only abstract method and attach a default no-op; the in-memory eventStream SHALL call attach with the same stream it later passes to drain, before it returns → `attach`, `Exchange.eventStream`
- SDS-AC-3 (IR-WS-002 AC-2): WHEN the WebSocketChannel methods are listed THE SYSTEM SHALL find IOException declared on sendText, sendBinary and ping only, and close, abort and isOpen without checked exceptions → `WebSocketChannel`
- SDS-AC-4 (IR-WS-002 AC-1): WHEN the WebSocketEndpoint methods are listed THE SYSTEM SHALL find exactly the four callbacks, none declaring an exception, and no class under NaruServe-tinyhttpd or testFixtures implementing the interface → `WebSocketEndpoint`
- SDS-AC-5 (IR-WS-002 AC-4): WHEN webSocket is called on an exchange that does not override it THE SYSTEM SHALL throw UnsupportedOperationException "webSocket is not supported by this adapter" without touching the exchange → `webSocket`
- SDS-AC-6 (IR-WS-002 AC-3): WHEN WebSocketSettings is read by reflection THE SYSTEM SHALL find a final class with only getters of int and long besides the constructor, passing the IR_ENGINE_002_AC3 value rule; a 4096 / 2000 ms app reads back 4096 and 2000 → `WebSocketSettings`
- SDS-AC-7 (IR-WS-002 AC-8): WHEN the in-memory exchange runs webSocket THE SYSTEM SHALL mark the exchange started with status 101, call onOpen on the exchange's worker thread, deliver queued peer events from that thread in order, and return only after onClose ran → `Exchange.webSocket`, `clientText`
- SDS-AC-8 (IR-WS-002 AC-8): WHEN the core calls close(code, reason) THE SYSTEM SHALL record it and have the peer echo it so onClose gets (code, reason); WHEN it calls abort THE SYSTEM SHALL set aborted and deliver onClose(1006, "") → `InMemoryWebSocketChannel.close`, `InMemoryWebSocketChannel.abort`
- SDS-AC-9 (IR-WS-002 AC-6): WHEN refuseWebSocket(e) is set THE SYSTEM SHALL throw e from webSocket before 101 with the exchange unstarted, so the error path's commit succeeds and onOpen never runs → `refuseWebSocket`
- SDS-AC-10 (IR-WS-002 AC-7): WHEN the frame-codec scan runs THE SYSTEM SHALL read every .java file under NaruServe-api/src/main and NaruServe-tinyhttpd/src/main and fail on "opcode" or "masking" in any case → `WebSocketChannel`
