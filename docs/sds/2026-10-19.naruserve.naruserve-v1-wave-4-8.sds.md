## Acceptance Contracts

- SDS-AC-1 (FR-APP-014 AC-1): WHEN any of the six app logger methods throws RuntimeException THE SYSTEM SHALL drop it inside SafeLogger, so the handler response, the standard 500 and the finish of an unfinished response proceed unchanged → `SafeLogger.info`, `SafeLogger.error`, `finish`
- SDS-AC-2 (FR-APP-014 AC-2): WHEN shutdown flushes and closes a logger whose flush and close throw THE SYSTEM SHALL catch both and still reach TERMINATED → `SafeLogger.flushAndClose`
- SDS-AC-3 (FR-APP-014 AC-3): WHEN formatting or writing an access line throws RuntimeException THE SYSTEM SHALL catch it inside write so nothing reaches the ExchangeHandler caller → `AccessLog.write`
- SDS-AC-4 (FR-APP-015 AC-1): WHEN defaults apply THE SYSTEM SHALL write exactly `GET /users/7 200 <n>ms in=0 out=5 rid=<16 hex>` through info; duration is (nanoTime at done − startNanos) / 1_000_000 → `AccessLog.format`, `next`
- SDS-AC-5 (FR-APP-015 AC-2): WHEN duration, bytes and rid are off THE SYSTEM SHALL drop each part with its leading space, and level selects the Logger method (TRACE..ERROR map to trace..error(String)) → `AccessLog.format`, `AccessLog.write`
- SDS-AC-6 (FR-APP-015 AC-3): WHEN the response ends ABORTED after commit THE SYSTEM SHALL log statusCode() followed by ` aborted`; every automatic reply, pre-request rejection and gate 503 SHALL call write exactly once → `onDone`, `statusCode`, `handle`
- SDS-AC-7 (FR-APP-015 AC-4): WHEN a stream response is copied THE SYSTEM SHALL fire onDone only after runTransfer ends and count out from the bytes written; a HEAD response counts 0 → `onDone`, `bytesWritten`
- SDS-AC-8 (FR-APP-015 AC-5): WHEN a handler reads 4 of 10 body bytes through the BodyState stream THE SYSTEM SHALL log in=4, never the declared Content-Length → `stream`, `bytesRead`
- SDS-AC-9 (FR-APP-015 AC-6): WHEN the raw path without query equals an exclude entry THE SYSTEM SHALL write no line; /health/x and /healthz still log; enabled(false) writes none → `DefaultAccessLogOptions.excluded`, `AccessLog.write`
- SDS-AC-10 (FR-APP-015 AC-7): WHEN a request gets a standard error body THE SYSTEM SHALL use the one rid from Dispatcher.handle for both the body requestId and the line → `handle`
- SDS-AC-11 (SEC-APP-001 AC-1): WHEN a line is formatted THE SYSTEM SHALL take only methodToken, rawPath (which excludes the query), status, numbers and rid, so no query, header or body byte can appear → `AccessLog.format`
- SDS-AC-12 (SEC-APP-001 AC-2): WHEN escape meets `\`, CR, LF, TAB or another char in U+0000–U+001F, U+007F, U+0080–U+009F THE SYSTEM SHALL emit `\\`, `\r`, `\n`, `\t` or `\u` plus 4 lowercase hex; percent-encoded text stays raw → `AccessLog.escape`
- SDS-AC-13 (SEC-APP-001 AC-3): WHEN write is called THE SYSTEM SHALL have no header parameter, so no header value can be logged → `AccessLog.write`

## Durable Rules

- Framework code logs only through SafeLogger; a logger failure is never a request or lifecycle failure.
