    - `reject(HttpServletResponse res, int status, boolean close): void` — setStatus, Content-Type ErrorRenderer.JSON_TYPE, Connection: close when asked, UTF-8 body from errorRenderer().render(status); never sendError, never a request-derived header or log text
- `NaruServe-servlet/src/main/java/com/snoworca/naruserve/servlet/ServletExchange.java` — one request and response over the container @req FR-SVL-002, FR-SVL-003

## Acceptance Contracts

- SDS-AC-1 (FR-SVL-002 AC-1): WHEN context path /app and pattern /api/* meet /app/api/users/%41;v=1?x=%20 THE SYSTEM SHALL give the route /users/:id rawPath /users/%41;v=1, id A;v=1 and x a space; with /* or / the /api part is not needed and the bare servlet root is / → `ServletPath.remainder`
- SDS-AC-2 (FR-SVL-002 AC-2): WHEN the raw URI misses contextPath + prefix at a segment boundary (/app/%61pi/users) THE SYSTEM SHALL answer 404 with the standard body and request id and never read getServletPath, getPathInfo or getParameter* → `NaruServeServlet.service`
- SDS-AC-3 (FR-SVL-002 AC-3): WHEN headers arrive THE SYSTEM SHALL give req.header and req.headers every value in per-name order, the Cookie header unchanged to the core parser, remoteAddress and isSecure from the container, and let trustProxy act in the core → `ServletExchange.headers`
- SDS-AC-4 (FR-SVL-002 AC-4): WHEN SharedApp runs on Jetty and on InMemoryHttpAdapter THE SYSTEM SHALL give identical statuses and bodies for params, query, JSON, cookies, 404, 405 Allow, HEAD, OPTIONS, middleware order, onError and res.file → `NaruServeServlet.service`
- SDS-AC-5 (FR-SVL-002 AC-5): WHEN raw request lines with bad percent-encoding, invalid UTF-8, encoded /, NUL, dot segments and OPTIONS * reach Jetty THE SYSTEM SHALL answer 400 or 404, never 2xx, pass the path on undecoded, and servlet.md SHALL record each observed status → `ServletPath.remainder`, `ServletDocsTest.observedStatuses`
- SDS-AC-6 (FR-SVL-002 AC-6): WHEN the adapter answers by itself THE SYSTEM SHALL write only fixed header values, no CR or LF, and log no token, session id or file content → `NaruServeServlet.reject`
- SDS-AC-7 (FR-SVL-003 AC-1): WHEN a handler sends 201, X-A: 1 and ok, or a stream of unknown length, or the core produces 404 or 500 THE SYSTEM SHALL pass status, headers and body through with the core's Content-Length and no container error page → `ServletExchange.commit`
- SDS-AC-8 (FR-SVL-003 AC-2): WHEN HEAD hits a GET route, or the status is 204 or 304 THE SYSTEM SHALL send the GET Content-Length and no body bytes → `ServletExchange.commit`
- SDS-AC-9 (FR-SVL-003 AC-3): WHEN abort ran THE SYSTEM SHALL fail the next write, commit or finish with IOException, accept a second abort and an abort from another thread, and throw IllegalStateException on a second commit or sendFile → `ServletExchange.abort`, `ServletExchange.requireStartable`
- SDS-AC-10 (FR-SVL-003 AC-4): WHEN res.file or res.download serves a whole file, one Range or a 416 THE SYSTEM SHALL match the in-memory adapter byte for byte, copy in chunks of at most 64 KiB without reading the file into memory and reference no java.nio.file type → `ServletExchange.sendFile`
- SDS-AC-11 (FR-SVL-003 AC-5): WHEN servlet.md is read THE SYSTEM SHALL say that response header order on the wire is the container's, and no shared case SHALL depend on header order → `ServletDocsTest.headerOrderSentence`

## Durable Rules

- The servlet never reads getServletPath, getPathInfo or getParameter* - the raw URI keeps encoded segments from changing the handler
- The adapter never calls sendError or setContentLength - the core owns the error body and Content-Length
