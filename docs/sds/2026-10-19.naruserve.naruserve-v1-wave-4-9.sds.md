## Acceptance Contracts

- SDS-AC-1 (FR-APP-016 AC-1): WHEN a LogcatLogger method runs THE SYSTEM SHALL call Log.v, d, i, w, e(tag,msg), e(tag,msg,t) resolved once in the constructor via Class.forName("android.util.Log") → `LogcatLogger`
- SDS-AC-2 (FR-APP-016 AC-2): WHEN the tag argument is null THE SYSTEM SHALL throw NullPointerException before the class lookup → `LogcatLogger.LogcatLogger`
- SDS-AC-3 (FR-APP-016 AC-3): WHEN android.util.Log is absent THE SYSTEM SHALL throw IllegalStateException whose message contains android.util.Log; a call that throws SHALL be swallowed → `LogcatLogger.LogcatLogger`, `LogcatLogger.invoke`
- SDS-AC-4 (FR-APP-016 AC-3): WHEN the absent case is tested THE SYSTEM SHALL load LogcatLogger through a URLClassLoader over the logcat and api main class dirs whose parent is the bootstrap loader, so test classes (the fake Log) stay hidden → `LogcatLogger`
- SDS-AC-5 (FR-APP-016 AC-4): WHEN logcat main classes are scanned THE SYSTEM SHALL find no android/ reference (existing checkClassReferences) and Log.java only under src/test → `LogcatLogger`
- SDS-AC-6 (FR-APP-017 AC-1): WHEN maxFileBytes, maxFiles or queueCapacity is below 1 THE SYSTEM SHALL throw IllegalArgumentException from the Builder setter → `RotatingFileLogger.Builder`, `RotatingFileLogger.builder`
- SDS-AC-7 (FR-APP-017 AC-2): WHEN writing the next line would make the file exceed maxFileBytes THE SYSTEM SHALL rotate before writing, formatting the IR-APP-006 console line itself (ConsoleLogger.format is package-private) → `RotatingFileLogger.rotate`
- SDS-AC-8 (FR-APP-017 AC-3): WHEN the queue is full THE SYSTEM SHALL drop with offer() and increment droppedCount without blocking → `RotatingFileLogger.droppedCount`
- SDS-AC-9 (FR-APP-017 AC-4): WHEN the directory cannot be created or a write fails THE SYSTEM SHALL drop and count the record in the writer thread; callers never see the exception → `RotatingFileLogger.droppedCount`
- SDS-AC-10 (FR-APP-017 AC-5): WHEN flush or close runs THE SYSTEM SHALL wait for a marker record behind the queued ones; after close no writer thread is alive and later calls are counted as dropped → `RotatingFileLogger.flush`, `RotatingFileLogger.close`
- SDS-AC-11 (FR-APP-017 AC-7): WHEN filelog tests block the writer THE SYSTEM SHALL use the package-private constructor with a StreamFactory whose stream waits on a latch → `RotatingFileLogger.RotatingFileLogger`, `RotatingFileLogger.StreamFactory`, `filelogTestFixtures`
- SDS-AC-12 (FR-APP-018 AC-1): WHEN a Slf4jLogger method runs THE SYSTEM SHALL call the same-named SLF4J method once with the same message and throwable → `Slf4jLogger`
- SDS-AC-13 (FR-APP-018 AC-2): WHEN new Slf4jLogger() runs THE SYSTEM SHALL request the name NaruServe from the test StaticLoggerBinder factory; a null delegate SHALL throw NPE → `Slf4jLogger.Slf4jLogger`
- SDS-AC-14 (CON-APP-001 AC-1): WHEN :NaruServe-api checkClassReferences runs THE SYSTEM SHALL fail on any org/slf4j/ or android/ reference → `classRefPrefixes`
- SDS-AC-15 (CON-APP-001 AC-2): WHEN the jars are built THE SYSTEM SHALL fail checkLoggerPlacement if a logger class sits in the api jar or is missing from its module jar → `checkLoggerPlacement`
