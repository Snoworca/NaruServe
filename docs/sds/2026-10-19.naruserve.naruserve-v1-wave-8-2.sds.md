## Acceptance Contracts

- SDS-AC-1 (FR-KT-003 AC-1): WHEN a single-abstract interface is a public method parameter type without @FunctionalInterface THE SYSTEM SHALL fail naming it; the real jar passes and a nested fixture proves the failure → `CallbackInventory.failures`, `CallbackInventory.inventory`
- SDS-AC-2 (FR-KT-003 AC-2): WHEN a name in the declared list is an interface with zero or two abstract methods THE SYSTEM SHALL fail naming it (a fixture with two abstract methods cannot carry @FunctionalInterface, so the declared list is the callback marker) → `CallbackInventory.failures`
- SDS-AC-3 (FR-KT-003 AC-3): WHEN each parameter of the matrix gets a Kotlin trailing lambda THE SYSTEM SHALL reach the lambda through a request or session, without a receiver DSL → `CallbackMatrixKotlinTest`
- SDS-AC-4 (FR-KT-003 AC-4): WHEN the reflection inventory names an interface that CALLBACK_TYPES lacks, or the reverse, THE SYSTEM SHALL fail the Java inventory test listing the difference → `CallbackMatrix`
- SDS-AC-5 (FR-KT-005 AC-1): WHEN a request lacks the value THE SYSTEM SHALL return null for query, cookie, header, form, file, lastEventId and attribute, declared as `String?`, `Cookie?` or `UploadFile?`, and the value when present → `NullableAccessorKotlinTest`
- SDS-AC-6 (FR-KT-005 AC-2): WHEN param names a missing pattern variable, or service names an unregistered type, THE SYSTEM SHALL throw (IllegalArgumentException for param), and queries and files SHALL return empty non-null lists → `NullableAccessorKotlinTest`
- SDS-AC-7 (FR-KT-005 AC-3): WHEN the body is JSON null THE SYSTEM SHALL give `User?` null from body(Class), and `List<User>?` from body(TypeRef) through a test JsonCodec → `NullableAccessorKotlinTest`
- SDS-AC-8 (FR-KT-005 AC-4): WHEN a table row has no `accessor_<name>` function THE SYSTEM SHALL fail the docs test naming the row → `NullableAccessorDocsTest.everyTableRowHasAFunction`
- SDS-AC-9 (IR-KT-001 AC-1): WHEN a Cookie setX exists THE SYSTEM SHALL find a getX or isX of the identical type (isX only boolean) and fail naming the property otherwise → `CookiePropertiesTest.properties`
- SDS-AC-10 (IR-KT-001 AC-2): WHEN Kotlin assigns the six cookie properties and calls res.addCookie THE SYSTEM SHALL read them back and emit the matching Set-Cookie header → `PropertySyntaxKotlinTest`
- SDS-AC-11 (IR-KT-001 AC-3): WHEN a handler reads res.isCommitted before and after res.send, req.isSecure, req.method() and req.path() THE SYSTEM SHALL give false, true, a Boolean and the call syntax with parentheses → `PropertySyntaxKotlinTest`
- SDS-AC-12 (IR-KT-001 AC-4): WHEN the Cookie properties are listed THE SYSTEM SHALL equal exactly name (read-only), value, path, domain, maxAge, secure, httpOnly, sameSite, the Kotlin names being name, value, path, domain, maxAge, secure, isHttpOnly, sameSite → `CookiePropertiesTest.properties`
