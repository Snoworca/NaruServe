## Acceptance Contracts

- SDS-AC-1 (FR-WS-009 AC-2): WHEN run passed the Origin check THE SYSTEM SHALL build the session, then call upgrade, which calls reserve before ex.webSocket, so a beforeOpen hook reads size() one higher → `upgrade`, `reserve`, `beforeOpen`
- SDS-AC-2 (FR-WS-009 AC-3): WHEN reserve returns false THE SYSTEM SHALL throw new HttpException(503).withHeader("Connection", "close") from upgrade without calling ex.webSocket → `upgrade`
- SDS-AC-3 (FR-WS-009 AC-4): WHEN ex.webSocket throws before onOpen THE SYSTEM SHALL remove the session and rethrow; a 403 or other core refusal throws before the session is built, so nothing is reserved → `upgrade`, `remove`
- SDS-AC-4 (FR-WS-009 AC-1): WHEN TinyHttpd refuses an upgrade beyond maxUpgradedConnections THE SYSTEM SHALL keep no NaruServe-side counter and answer with the mapped 503 + Retry-After of FR-WS-002, its reservation removed by SDS-AC-3 → `reserve`
- SDS-AC-5 (FR-WS-009 AC-5): WHEN opening reads CLOSING THE SYSTEM SHALL call closeBy(1001, "server shutdown") as the only task, skip the handler and the idle watch → `opening`
- SDS-AC-6 (FR-WS-010 AC-1): WHEN closeAll runs THE SYSTEM SHALL, in one synchronized block, set CLOSING and copy the reserved and open sessions; reserve SHALL return false from then on → `closeAll`, `State`
- SDS-AC-7 (FR-WS-010 AC-3): WHEN the snapshot is taken THE SYSTEM SHALL call closeBy(1001, "server shutdown") on every opened session, whose last() discards the queue and refuses later sends, so no separate stop of the executor is needed → `closeAll`
- SDS-AC-8 (FR-WS-010 AC-5): WHEN the close wait runs THE SYSTEM SHALL end it at min(now + 1000 ms, deadlineNanos), and earlier only when every snapshot session is removed or opened with awaitIdleUntil true → `closeAll`, `awaitIdleUntil`
- SDS-AC-9 (FR-WS-010 AC-4): WHEN the close wait ends THE SYSTEM SHALL set ENDED under the lock first and then call abort() on each snapshot session with a channel whose slot is not idle → `closeAll`
- SDS-AC-10 (FR-WS-010 AC-6): WHEN a reserved session opens during CLOSING THE SYSTEM SHALL count its close task in the same wait, because it is in the snapshot and not yet removed → `closeAll`, `opening`
- SDS-AC-11 (FR-WS-010 AC-7): WHEN opening reads ENDED THE SYSTEM SHALL call abort() at once with no closeBy, so no pair is recorded and the close line reports 1006 → `opening`
- SDS-AC-12 (FR-WS-010 AC-8): WHEN terminate runs after the adapter stop THE SYSTEM SHALL call shutdownNow(500) on the sender and the idle scheduler and then clear the registry → `terminate`, `shutdownNow`, `WebSocketIdleScheduler.shutdownNow`
- SDS-AC-13 (FR-WS-010 AC-1): WHEN freeze builds the dispatcher THE SYSTEM SHALL register closeAll in BEFORE_WAIT and terminate in FORCE_CLOSE once per app → `DefaultRestApp.freeze`, `webSocketRegistry`
