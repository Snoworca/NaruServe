## Acceptance Contracts

- SDS-AC-1 (FR-HTTP-002 AC-2): WHEN an exchange arrives THE SYSTEM SHALL check in order: method OPTIONS with raw path * gives 204, any raw path not starting with / gives 400, PathValidator.isValid false gives 400, then Router.lookup → `Dispatcher.preCheck`, `Dispatcher.handle`
- SDS-AC-2 (FR-HTTP-002 AC-4): WHEN preCheck or a non-MATCHED lookup answers THE SYSTEM SHALL write the reply through the exchange directly, building no DefaultRequest or DefaultResponse → `Dispatcher.automatic`
- SDS-AC-3 (FR-HTTP-003 AC-2): WHEN an Allow header is written THE SYSTEM SHALL join RouteMatch.allow() (or Method.any() for OPTIONS *) with ", " in MethodSet iteration order → `Dispatcher.allowHeader`
- SDS-AC-4 (FR-HTTP-003 AC-5): WHEN lookup is called THE SYSTEM SHALL pass Router.isWebSocketUpgrade(token, Connection, Upgrade) with each header's values joined by ", " → `Dispatcher.handle`
- SDS-AC-5 (FR-HTTP-003 AC-6): WHEN lookup gives WEBSOCKET_ONLY, or MATCHED with routeKind WEBSOCKET, THE SYSTEM SHALL answer 426 with Upgrade: websocket, Connection: Upgrade and Content-Length: 0 and never call the route handler → `Dispatcher.automatic`
- SDS-AC-6 (FR-HTTP-003 AC-3): WHEN the automatic status is 204 THE SYSTEM SHALL commit with content length 0 and add no Content-Length header; every other automatic status SHALL carry Content-Length: 0 → `Dispatcher.automatic`
- SDS-AC-7 (FR-HTTP-004 AC-2): WHEN RouteMatch.autoHead() is true THE SYSTEM SHALL call the GET handler with a request whose method() is HEAD and a response built in HEAD mode → `Dispatcher.invoke`
- SDS-AC-8 (FR-HTTP-006 AC-2): WHEN a handler throws an Exception while the response is NEW THE SYSTEM SHALL drop the status and headers it set and commit 500 with only Content-Length: 0; the exception is not rethrown to the adapter → `Dispatcher.invoke`
- SDS-AC-9 (FR-HTTP-006 AC-3): WHEN a handler throws while the response is STREAMING THE SYSTEM SHALL call abort; when it is COMPLETED or ABORTED THE SYSTEM SHALL do nothing more → `Dispatcher.invoke`
- SDS-AC-10 (FR-HTTP-006 AC-4): WHEN a handler returns with the response NEW THE SYSTEM SHALL call end(), and with it STREAMING SHALL run the pending stream copy on the same adapter thread → `Dispatcher.invoke`
- SDS-AC-11 (FR-HTTP-007 AC-1): WHEN app.get(p, h) or a builder get(h) registers THE SYSTEM SHALL record the same Registration (MethodSet.of(GET), p, HTTP) so freeze reports the pair as a duplicate → `DefaultRestApp.route`, `DefaultRouteBuilder`
- SDS-AC-12 (FR-HTTP-008 AC-4): WHEN Router.freeze throws RoutingConfigException THE SYSTEM SHALL propagate it from freeze unchanged and leave the app unfrozen, so dispatcher() keeps throwing IllegalStateException → `DefaultRestApp.freeze`, `DefaultRestApp.dispatcher`
- SDS-AC-13 (FR-HTTP-008 AC-5): WHEN any registration, webSocketRoute or routerPolicy call (including through a DefaultRouteBuilder) runs after a successful freeze THE SYSTEM SHALL throw IllegalStateException and record nothing → `DefaultRestApp.route`, `DefaultRestApp.webSocketRoute`
- SDS-AC-14 (FR-HTTP-008 AC-1): WHEN the implementation is placed THE SYSTEM SHALL put it in com.snoworca.naruserve.internal as a public class, with that package's javadoc stating it is not API → `DefaultRestApp`

## Durable Rules

- Dispatcher is the only place that maps RouteMatch kinds and pre-checks to HTTP statuses — the router stays engine-free and every adapter answers identically.
- Pre-checks (OPTIONS *, non-/ path, PathValidator) run before any Request is built — later middleware and onError may assume a non-null Method and decoded path.
