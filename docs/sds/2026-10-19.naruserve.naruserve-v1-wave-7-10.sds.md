## Acceptance Contracts

- SDS-AC-1 (FR-SSE-002 AC-1): WHEN send is called THE SYSTEM SHALL serialise before taking the lock and add the whole byte[] as one queue entry, so one event is one write and entries keep call order → `DefaultSseClient.send`
- SDS-AC-2 (FR-SSE-002 AC-3): WHEN the drain waits THE SYSTEM SHALL wait on the client lock with the time left until lastWrite + heartbeat and then write ": ping\n\n" itself, flushing after each event and each ping; no timer thread exists → `DefaultSseClient.drain`
- SDS-AC-3 (FR-SSE-002 AC-4): WHEN queuedBytes + n > sendQueueSize for a queued send THE SYSTEM SHALL drop the event, clear the queue, call endBy("overflow") and return false; the running write is not interrupted → `DefaultSseClient.send`, `endBy`
- SDS-AC-4 (FR-SSE-002 AC-5): WHEN send runs on handlerThread, a stream is attached and the drain has not started THE SYSTEM SHALL take writeLock, write every queued entry in order and then its own event to the attached stream, flush, and return true; an IOException there SHALL end the stream with cause client and return false → `DefaultSseClient.send`, `DefaultSseClient.attach`
- SDS-AC-5 (FR-SSE-002 AC-6): WHEN drain starts THE SYSTEM SHALL set draining under the client lock and then take writeLock, so a handler-thread write in progress finishes before the first drain write → `DefaultSseClient.drain`
- SDS-AC-6 (FR-SSE-002 AC-8): WHEN no stream was attached THE SYSTEM SHALL queue handler-thread sends under the limit like any other thread's → `DefaultSseClient.send`
- SDS-AC-7 (FR-SSE-002 AC-7): WHEN the client is ended THE SYSTEM SHALL return false from send before encoding is queued, and the drain SHALL clear the queue when it returns, so queuedBytes() is 0 → `queuedBytes`, `DefaultSseClient.send`
- SDS-AC-8 (FR-SSE-004 AC-3): WHEN ended is set and the queue is empty THE SYSTEM SHALL return from the loop, call res.sseEnded(null), remove the client from the registry and then runListeners, so the body ends before onClose runs → `DefaultSseClient.drain`, `sseEnded`
- SDS-AC-9 (FR-SSE-004 AC-5): WHEN a drain write throws IOException THE SYSTEM SHALL endBy("client"), RuntimeException endBy("error"), then res.sseEnded(e) and runListeners; nothing is rethrown → `DefaultSseClient.drain`, `endBy`
- SDS-AC-10 (FR-SSE-004 AC-4): WHEN onClose is registered THE SYSTEM SHALL add it under the lock unless the listeners already ran, else run it at once on the caller; a throw is logged at ERROR with the rid and swallowed → `DefaultSseClient.onClose`, `runListeners`
- SDS-AC-11 (FR-SSE-004 AC-6): WHEN sse() runs for HEAD THE SYSTEM SHALL commit the headers bodyless through the end() path, never call ex.eventStream or register, and return ended(rid, log); sseClient() stays null → `ended`, `sseClient`
- SDS-AC-12 (FR-SSE-004 AC-8): WHEN drain starts on a thread not marked THE SYSTEM SHALL call lifecycle.enterRequest() and exitRequest() in finally after runListeners; a thread already marked is left as it is → `DefaultSseClient.drain`
- SDS-AC-13 (FR-SSE-004 AC-5): WHEN the response aborts before any drain started THE SYSTEM SHALL endBy("error") and run the listeners from abort; a later drain call returns at once → `DefaultResponse.abort`
- SDS-AC-14 (FR-SSE-002 AC-2): WHEN the in-memory eventStream runs THE SYSTEM SHALL record writer threads and the attach and drain instances in the InMemoryEventStream returned by nextEventStream → `nextEventStream`, `writerThreads`, `attached`
