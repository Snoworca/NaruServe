### Files

- `NaruServe-tinyhttpd/src/main/java/com/snoworca/naruserve/tinyhttpd/TinyHttpdEventStream.java` — the TinyHttpd event-stream class; chunked body, never startEventStream @req FR-SSE-003
  - `final class TinyHttpdEventStream` — no instance; static start plus two nested types
    - `start(TinyHttpdExchange ex, Response res, int status, List<Map.Entry<String, String>> headers, StreamDrain drain): void` — lock, slot, headers, flush, attach, register ← TinyHttpdFeatures.eventStream
    - `Slots` — the NaruServe SSE counter of one bound server, built from maxSseStreams
      - `tryAcquire(): boolean` / `release(): void` / `open(): int` — AtomicInteger compare-and-set below the max
    - `Body` — FilterOutputStream over res.getOutputStream(); write and flush synchronized (ex) with the abort check; flush calls res.flushBuffer()
- `NaruServe-tinyhttpd/src/main/java/com/snoworca/naruserve/tinyhttpd/TinyHttpdFeatures.java` — eventStream body @req FR-SSE-003
  - `TinyHttpdFeatures.eventStream(TinyHttpdExchange ex, int status, List<Map.Entry<String, String>> headers, StreamDrain drain): void` — delegates to TinyHttpdEventStream.start
- `NaruServe-tinyhttpd/src/main/java/com/snoworca/naruserve/tinyhttpd/TinyHttpdExchange.java` — drain run on the worker after the handler @req FR-SSE-003
  - `TinyHttpdExchange.run(Request req, Response res, ExchangeHandler handler, TinyHttpdEventStream.Slots slots): void` — handler, then the registered drain, then the end wait; slot released in finally
  - `register(StreamDrain drain, OutputStream out, boolean slot): void` — stores the drain to run and whether a slot is held ← start
  - `slots(): TinyHttpdEventStream.Slots` — the server's counter ← start
- `NaruServe-tinyhttpd/src/main/java/com/snoworca/naruserve/tinyhttpd/TinyHttpdAdapter.java` — one Slots per bind; maxEventStreams mapping unchanged @req FR-SSE-003
  - `TinyHttpdAdapter.bind(ServerSettings settings, ExchangeHandler handler): void` — new Slots(settings.maxSseStreams()) passed to every run
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/SseRegistry.java` — open streams of one app, closed flag and the closing participant @req FR-SSE-005
  - `SseRegistry(DefaultSseOptions options, @Nullable AppLifecycle lifecycle, SafeLogger log)` — built at freeze ← DefaultRestApp
  - `enum State` — OPEN, CLOSED (flag set; no close wait, so no third state)
  - `register(DefaultSseClient client): boolean` / `remove(DefaultSseClient client): void` / `size(): int` / `state(): State` — synchronized
  - `options(): DefaultSseOptions` / `lifecycle(): @Nullable AppLifecycle` — read by DefaultSseClient
  - `closeAll(long deadlineNanos): void` — the before-wait participant; flag, snapshot, closing() on each, returns without waiting
  - `terminate(): void` — the force-close participant; endBy("shutdown") and queue clear on any stream left, then clears the registry
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultSseClient.java` — the shutdown end of one stream @req FR-SSE-005
  - `closing(): void` — under the lock: when not ended, append the notice past the limit, then endBy("shutdown"); notifies the drain
  - `static final byte[] NOTICE` — "event: shutdown\ndata: shutdown\n\n" in UTF-8
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultRestApp.java` — SSE registry built and participants registered at freeze @req FR-SSE-005
  - `DefaultRestApp.freeze(): void` — builds SseRegistry(sseOptions().copy(), lifecycle, safe), passes it to the Dispatcher; BEFORE_WAIT sseRegistry::closeAll, FORCE_CLOSE sseRegistry::terminate
  - `sseRegistry(): SseRegistry` — package-private, read by internal tests

## Acceptance Contracts

- SDS-AC-1 (FR-SSE-003 AC-6): WHEN start runs THE SYSTEM SHALL, inside one synchronized (ex), call requireStartable, then tryAcquire, then set started through the FR-WS-002 markUpgraded; the header set, flush, attach and register run after the lock is released → `start`, `tryAcquire`
- SDS-AC-2 (FR-SSE-003 AC-4): WHEN tryAcquire fails THE SYSTEM SHALL throw new HttpException(503) with the exchange unstarted, so DefaultResponse.sse leaves NEW and the error path commits 503 with the request id → `start`
- SDS-AC-3 (FR-SSE-003 AC-1): WHEN the headers are written THE SYSTEM SHALL setStatus and setHeader each pair, set no Content-Length, and flush once through Body before attach, so TinyHttpd frames the body chunked and the client sees the headers at once → `start`, `Body`
- SDS-AC-4 (FR-SSE-003 AC-6): WHEN start registers THE SYSTEM SHALL call drain.attach(body) and register(drain, body, true) with the same Body instance → `start`, `register`
- SDS-AC-5 (FR-SSE-003 AC-2): WHEN handler.handle returns and a drain is registered and the exchange is not aborted THE SYSTEM SHALL call drain.drain(body) on the same worker before ended.await(); a RuntimeException from it aborts the exchange → `TinyHttpdExchange.run`
- SDS-AC-6 (FR-SSE-003 AC-7): WHEN run leaves for any reason THE SYSTEM SHALL release the slot in finally when register recorded one, so a new stream is accepted after one ended → `TinyHttpdExchange.run`, `release`
- SDS-AC-7 (FR-SSE-003 AC-8): WHEN Body.flush is called THE SYSTEM SHALL call res.flushBuffer() under synchronized (ex), passing every event and ping flush of the core drain to the socket → `Body`
- SDS-AC-8 (FR-SSE-003 AC-5): WHEN the adapter binds THE SYSTEM SHALL keep maxEventStreams(s.maxSseStreams()) and size Slots from the same value; no class calls startEventStream → `TinyHttpdAdapter.bind`, `Slots`
- SDS-AC-9 (FR-SSE-005 AC-1): WHEN closeAll runs THE SYSTEM SHALL set CLOSED and copy the open streams in one synchronized block; register SHALL return false from then on → `closeAll`, `register`
- SDS-AC-10 (FR-SSE-005 AC-3): WHEN closing appends the notice THE SYSTEM SHALL add NOTICE to the queue without the sendQueueSize check and count its bytes, so a near-full stream ends with cause shutdown, never overflow → `closing`, `NOTICE`
- SDS-AC-11 (FR-SSE-005 AC-4): WHEN closeAll has called closing on every snapshot stream THE SYSTEM SHALL return at once, never joining or waiting on a drain, and ignore deadlineNanos → `closeAll`
- SDS-AC-12 (FR-SSE-005 AC-6): WHEN terminate runs after the adapter stop THE SYSTEM SHALL clear each remaining stream's queue and the registry, so size() is 0 and queuedBytes() is 0 → `terminate`, `size`
- SDS-AC-13 (FR-SSE-005 AC-1): WHEN freeze runs THE SYSTEM SHALL register closeAll in BEFORE_WAIT before the WebSocket closeAll, and terminate in FORCE_CLOSE, once per app → `DefaultRestApp.freeze`, `sseRegistry`
