### Files

- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/WebSocketUpgrade.java` — app-wide session id counter @req FR-WS-006
  - `nextId(): String` — String.format("%016x", counter.incrementAndGet()) of one AtomicLong per WebSocketUpgrade ← run
- `NaruServe-api/src/main/java/com/snoworca/naruserve/internal/DefaultWebSocketSession.java` — id, attributes, sends, close validation and listener semantics @req FR-WS-006
  - `DefaultWebSocketSession(String id, String requestId, WebSocketUpgrade upgrade, @Nullable WebSocketHandler handler, DefaultRequest req)` — reads codec, logger, sender, idle scheduler and registry from upgrade ← run
  - `id(): String` — the nextId value given at construction
  - `DefaultWebSocketSession.attribute(String key, @Nullable Object value): void` / `<T> @Nullable T DefaultWebSocketSession.attribute(String key, Class<T> type)` — own ConcurrentHashMap; never the request's map
  - `attributeCount(): int` — size of the attribute map, read by tests
  - `sendText(String text): void` / `sendBinary(byte[] data): void` / `sendJson(@Nullable Object value): void` — dropped when not open; otherwise handed to the sender slot
  - `checkClose(int code, String reason): void` — static; IllegalArgumentException for a code outside 1000-1003, 1007-1014, 3000-4999 or a reason over 123 UTF-8 bytes
  - `closeBy(int code, String reason): void` — every close the core starts; records the first (code, reason) pair only, sets isOpen false, submits channel.close as the last task
  - `fail(Exception error, String what): void` — onError listeners, ERROR log with the request id, then closeBy(1011, "")
  - `DefaultWebSocketSession.onText(String text): void` / `DefaultWebSocketSession.onBinary(byte[] data): void` — endpoint callbacks; listener exceptions go to fail
  - `DefaultWebSocketSession.onJson(Class<T> type, JsonListener<T> listener): void` — registered in the text listener list as a decoding entry
  - `DefaultWebSocketSession.onClose(int code, String reason): void` — runs the CloseListeners once, then clears the attributes
  - `DefaultWebSocketSession.onOpen(WebSocketChannel channel): void` — handler exceptions go to fail
- `NaruServe-api/src/testFixtures/java/com/snoworca/naruserve/testing/InMemoryWebSocketChannel.java` — test-side blocking hook @req FR-WS-006
  - `hold(String method): CountDownLatch` — the next call of that channel method waits until the returned latch is counted down

## Acceptance Contracts

- SDS-AC-1 (FR-WS-006 AC-1): WHEN a session is built THE SYSTEM SHALL take its id from nextId of the app's one WebSocketUpgrade, so ids are unique per app and restart at 0000000000000001 in a new app → `nextId`, `id`
- SDS-AC-2 (FR-WS-006 AC-2): WHEN attribute is set with a null value THE SYSTEM SHALL remove the key, and the typed read SHALL box a primitive class through DefaultRequest.wrapper as Request.attribute does → `DefaultWebSocketSession.attribute`
- SDS-AC-3 (FR-WS-006 AC-2): WHEN the onClose listeners have run THE SYSTEM SHALL clear the attribute map, so attributeCount() is 0 afterwards → `DefaultWebSocketSession.onClose`, `attributeCount`
- SDS-AC-4 (FR-WS-006 AC-3): WHEN the endpoint onClose is called more than once THE SYSTEM SHALL run the listeners only on the first call, guarded by one AtomicBoolean, on the calling thread in registration order; a CloseListener exception is logged at ERROR and the next listener still runs → `DefaultWebSocketSession.onClose`
- SDS-AC-5 (FR-WS-006 AC-4): WHEN sendJson is called on an open session THE SYSTEM SHALL encode on the calling thread with codec.encode into a StringWriter and queue the result as a text message; an IOException from the codec SHALL be rethrown as UncheckedIOException with nothing queued → `sendJson`
- SDS-AC-6 (FR-WS-006 AC-4): WHEN a text message arrives THE SYSTEM SHALL run onText and onJson entries in one registration-ordered list, each onJson entry decoding with codec.decode(new StringReader(text), type) on its own → `DefaultWebSocketSession.onJson`, `DefaultWebSocketSession.onText`
- SDS-AC-7 (FR-WS-006 AC-5): WHEN decode throws IOException or RuntimeException THE SYSTEM SHALL skip that listener, pass the exception to each onError listener, run the later entries and keep the session open; with no onError listener it SHALL log WARN "websocket <rid> json decode failed" → `DefaultWebSocketSession.onJson`
- SDS-AC-8 (FR-WS-006 AC-6): WHEN a text, binary or JSON listener throws THE SYSTEM SHALL call fail(e, "listener"), skip the remaining listeners of that message and return normally to the adapter; the ERROR line reads "websocket <rid> listener failed" → `fail`, `DefaultWebSocketSession.onText`
- SDS-AC-9 (FR-WS-006 AC-6): WHEN an onError listener itself throws THE SYSTEM SHALL log it at ERROR, ignore it and still run the next onError listener and the 1011 close, with no recursion into fail → `fail`
- SDS-AC-10 (FR-WS-006 AC-7): WHEN a send or ping is called and isOpen() is false THE SYSTEM SHALL return before encoding or counting bytes → `sendText`, `sendBinary`, `sendJson`
- SDS-AC-11 (FR-WS-006 AC-8): WHEN close(code, reason) is called THE SYSTEM SHALL run checkClose first, also on a closed session, with messages "close code must be 1000-1003, 1007-1014 or 3000-4999: <code>" and "close reason over 123 UTF-8 bytes: <n>" → `checkClose`
- SDS-AC-12 (FR-WS-006 AC-9): WHEN several closes are started by the core (close, overflow 1008, idle 1001, shutdown 1001, failure 1011) THE SYSTEM SHALL report the first recorded pair to onClose, and with no recorded pair the code the adapter delivers → `closeBy`, `DefaultWebSocketSession.onClose`
- SDS-AC-13 (FR-WS-006 AC-10): WHEN the handler throws from onOpen THE SYSTEM SHALL call fail(e, "handler") with only the onError listeners registered before the throw, log "websocket <rid> handler failed" and write no HTTP answer → `DefaultWebSocketSession.onOpen`, `fail`
