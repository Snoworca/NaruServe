## C-07 implementer decisions (state them in the AC as "Decision: ...")

WebSocket API (package com.snoworca.naruserve):
- `RestApp ws(String path, WebSocketHandler handler)` returns the same `RestApp` (app.md "ws return type" marker settled: `RestApp`, like `get`). Callback interface name: `WebSocketHandler` (`@FunctionalInterface`, `void handle(Request req, WebSocketSession ws) throws Exception`) — app.md "ws callback name" marker settled. Pattern syntax and freeze/conflict rules are the HTTP route rules (registered through the existing Router.addWebSocket path; the internal DefaultRestApp.webSocketRoute hook becomes the implementation of `ws`). `ws` is under the NEW-state guard of FR-APP-002; `null` path/handler -> NullPointerException.
- `RestApp webSocket(Configurer<WebSocketOptions> configurer)`; public interface `WebSocketOptions` with fluent setters: `allowedOrigins(String... origins)` (default: none configured), `maxMessageSize(int bytes)` default 1048576, range 1..16777216; `sendQueueSize(int bytes)` default 1048576, range 1..67108864; `pingInterval(long time, TimeUnit unit)` default 30 s, range 1 s..1 h; `idleTimeout(long time, TimeUnit unit)` default 300 s (5 min), range 1 s..24 h. Out of range -> IllegalArgumentException naming the setting (`<setting> must be in <lo>..<hi>: <value>` like MultipartOptions); no value means unlimited (I-012). Configurer runs on a copy swapped in after it returned (like multipart). No handshake-timeout setting (residual r5 W2-002). No pong-timeout setting (D-424: equals ping interval).
- Origin (W2-005): no allowlist configured -> admit a request with no `Origin` and a same-origin `Origin` (scheme, host and port equal to the request's: scheme `https` when `req.isSecure()` else `http`, host and port from `Host`, default ports 80/443 normalised, host compared case-insensitively); reject every other `Origin` (including the literal `null`) with `403` before the upgrade extension point. A configured allowlist admits the same-origin/no-Origin cases plus each listed origin (compared case-insensitively after default-port normalisation); entry `*` admits any origin. `allowedOrigins()` with no argument resets to the default.
- `WebSocketSession` methods: `String id()`, `void sendText(String)`, `void sendBinary(byte[])`, `void sendJson(@Nullable Object)`, `void ping()`, `void close()` (= `close(1000, "")`), `void close(int code, String reason)`, `boolean isOpen()`, `void onText(WebSocketSession.TextListener)`, `void onBinary(BinaryListener)`, `<T> void onJson(Class<T> type, JsonListener<T>)`, `void onClose(CloseListener)`, `void onError(ErrorListener)`, `void attribute(String key, @Nullable Object value)`, `<T> @Nullable T attribute(String key, Class<T> type)` (same overload rule as Request). Nested `@FunctionalInterface` listeners: `TextListener.onText(String) throws Exception`, `BinaryListener.onBinary(byte[]) throws Exception`, `JsonListener<T>.onJson(@Nullable T value) throws Exception`, `CloseListener.onClose(int code, String reason) throws Exception`, `ErrorListener.onError(Throwable error) throws Exception`. Several listeners of one kind run in registration order.
- Session id: 16 lowercase hex digits of an app-wide counter starting at 1 (unique within one app, D-312).
- Sends: `sendText`/`sendBinary`/`sendJson`/`ping` on a closed session are dropped without exception (`isOpen()` reports the state), like the `ws` library's send on a closed socket. `close(code, reason)` validates code per RFC 6455 (1000..4999 excluding 1004, 1005, 1006, 1015 -> otherwise IllegalArgumentException) and truncates nothing (reason over 123 UTF-8 bytes -> IllegalArgumentException).
- Overflow policy (D-321): when queuing a message would make the session's queued bytes exceed `sendQueueSize`, the message is dropped, the session discards its queue, hands close `1008` with reason `send queue overflow` to its sender slot as last task, and `onClose` receives 1008; the overflowing send call itself returns normally (no exception). Rejected alternative: throwing from send (forces every broadcaster to catch; reopen if users need synchronous backpressure).
- `onJson` parse failure (D-317): the decode exception is passed to the `onError` listeners and the session stays open; when no `onError` listener is registered it is logged at WARN with the request id. Rejected: closing 1007 (a malformed app message is not a protocol error).
- User listener exceptions after `101` (r2 W2-005): caught, logged at ERROR with request id, session closed with 1011; `onError` listeners also receive it before the close. No exception reaches TinyHttpd.
- Access-log lines: handshake line is the D-173 line `GET <path> 101[ <n>ms][ in=0 out=0][ rid=<id>]` written in onOpen; close line `WS <path> <closeCode>[ <n>ms][ rid=<id>]` where duration runs from onOpen to close; both at the configured level and suppressed for excluded paths or `enabled(false)`.

SSE API:
- `Response.sse()` returns `SseClient` (default method on `Response` throws UnsupportedOperationException like json/cookie; DefaultResponse implements). Calling it on a committed response -> IllegalStateException.
- `RestApp sse(Configurer<SseOptions> configurer)`; public interface `SseOptions`: `heartbeatInterval(long time, TimeUnit unit)` default 15 s, range 1 s..1 h; `sendQueueSize(int bytes)` default 262144 (256 KiB), range 1..16777216. Same range/copy rules as WebSocketOptions.
- `SseClient`: `boolean send(String event, String data)`, `boolean send(String data)` (data-only event, no `event:` line), `boolean send(SseEvent event)`, `void close()` (ends the stream normally: drain writes queued events, ends the chunked body, runs onClose), `boolean isOpen()`, `void onClose(SseClient.CloseListener listener)`; `CloseListener.onClose() throws Exception` (`@FunctionalInterface`). `send` returns `true` when the event was written or queued and `false` when the client has ended (closed, disconnected, overflowed, shutdown, HEAD). `onClose` registered on an ended client runs at once, once, on the calling thread (sse.md marker settled). Listener exceptions are logged at ERROR and the other listeners still run.
- `SseEvent`: only the factory `static SseEvent event(String name)` plus instance `id(String)`, `data(String)`, `retry(long millis)`; immutable-copy builder or fluent mutable is the implementer's choice but each setter returns `SseEvent`. Name or id containing CR, LF or NUL -> IllegalArgumentException; `retry` negative -> IllegalArgumentException; data `null` -> empty `data:` line. Serialisation order `event`, `id`, `retry`, `data` lines, then blank line; lines end with `\n`.
- Overflow policy (D-406/D-339): a non-handler-thread send that would exceed `sendQueueSize` ends the stream: the event is dropped, queued events are discarded, the stream ends (chunked body ended), onClose runs, and that send returns `false`. Rejected alternative: blocking the sender (stalls app threads; reopen on demand).
- Closing notice (D-436 form): the event `event: shutdown\ndata: shutdown\n\n` (dispatched to EventSource listeners of `shutdown`; data non-empty because EventSource drops empty-data events), exempt from the queue limit.
- Heartbeat: comment line `: ping\n\n` after one heartbeat interval with nothing written.
- SSE access log: the one D-173 line is written when the stream ends: `GET <path> 200[ <n>ms][ in=<i> out=<o>][ rid=<id>] sse start=<epochMillis> cause=<client|app|overflow|shutdown|error>` (duration = whole stream; out = bytes written).

HttpException (HTTP scope, W2-002): `HttpException withHeader(String name, String value)` returns `this`; `List<Map.Entry<String, String>> headers()` unmodifiable, insertion order, empty by default; name/value validated like `res.header` (CR, LF -> IllegalArgumentException; null -> NullPointerException). Error path sets these headers on the standard error response (after dropping app-set headers per FR-APP-005 AC-4), also when an onError handler leaves the response NEW; an onError handler that answers itself decides its own headers.

Shutdown (APP):
- `ShutdownParticipants` gains an add-only overload taking a participant that receives the D-162 deadline (`long deadlineNanos`); existing Runnable participants unchanged.
- D-344 margin: 3 s (TinyHttpd stop overrun up to 1.5 s + adapter release up to 1 s + 0.5 s scheduling slack), recorded in lifecycle.md and used as T44 tolerance.
- Thread totals (D-416 + W2-006): 452 threads (192 workers, 128 WS read, 128 WS sender, 1 idle scheduler, acceptor, watchdog, keeper); stack figure 449 request-path threads = 112.25 MiB.
